---

## 一句话结论（TL;DR）

模型层是**纯数据 + 手写 JSON 解析**，没有 `json_serializable` / `freezed` / 代码生成，全部 `fromJson` 走 `asString` / `asInt` / `asList` / `asMap` 四个容错辅助函数，**类型不符与字段缺失一律降级为 `null` 或固定默认值，从不抛异常**。
同一语义在不同模型里字段名/JSON 键不统一（`coverUrl` / `pic` / `picUrl` / `sizable_cover` / `union_cover`；`error_code` / `errorCode` / `err_code`），改接口前必须先查 §4。
缓存序列化统一走 `toCache` / `fromCache`（camelCase 键），**只有 `LyricCandidate` 与 `LoudnessData` 提供 `toJson`**。

### 1.2 解析模式

- 每个类都有 `const` 构造器 + `factory X.fromJson(Map<String, dynamic> json)`；**没有 `toJson` 的类不支持反向序列化**。
- 需要落盘的类额外提供 `toCache()` / `fromCache()`：`Song`、`PlaylistSummary`、`UserProfile`、`DailyRecommend`、`AlbumShopItem`、`LyricLine`、`LyricWord`。
- 列表项一律 `asList(...).whereType<Map>()`（或 `whereType<Map<String, dynamic>>()`）+ `.map(X.fromJson)`，并在必要处 `.where(...)` 过滤空键；**解析失败的条目被静默丢弃，不报错、不计数**。
- 嵌套对象用 `json['k'] is Map ? X.fromJson(asMap(json['k'])) : null` 判型，`is List` 同理（见 `MusicCommentItem.fromJson`，`music_models.dart:1573-1606`）。

## 2. JSON 容错契约（辅助函数）

所有解析入口都依赖下列函数（`music_models.dart:1766-1829`），行为如下——**这是理解全部 `fromJson` 的前置知识**。

| 函数 | 锚点 | 入参 null | 类型不符 | 空串/空白串 | 备注 |
|---|---|---|---|---|---|
| `asString(Object?)` | `music_models.dart:1766` | 返回 null | `value.toString().trim()`（任意类型都能转） | 返回 null（`text.isEmpty ? null`） | 数字会被转成字符串 |
| `asInt(Object?)` | `music_models.dart:1774` | 返回 null | `int.tryParse(value.toString())`；失败返回 null | 返回 null | `"12.5"` 与 `12.0` 都得到 null |
| `asList(Object?)` | `music_models.dart:1784` | 返回 `const []` | 返回 `const []` | — | 不抛错，只认 `List` |
| `asMap(Object?)` | `music_models.dart:1791` | 返回 `const {}` | `Map` 会按 `key.toString()` 重建；其它返回 `const {}` | — | 返回不可变空 Map，**调用方不可写入** |
| `durationFromSeconds` | `music_models.dart:1801` | null | 同 `asInt` | — | 秒 → `Duration` |
| `durationFromMilliseconds` | `music_models.dart:1806` | null | 同 `asInt` | — | 毫秒 → `Duration` |
| `normalizeImageUrl(String?, {size=480})` | `music_models.dart:1811` | 返回 null | — | 原样返回 | 替换 `{size}` / `{SIZE}` / `/{size}/` / `/{SIZE}/` 为 `480` |

### 2.1 `parseArtists` 的键优先级（`music_models.dart:982-1054`）

| 阶段 | 取值顺序 |
|---|---|
| 容器键 | `singerinfo` → `authors` → `author` → `singers` → `Singers`，最后再尝试**根对象自身** |
| id 键 | `id` → `author_id` → `AuthorID` → `AuthorId` → `singerid` → `singer_id` → `SingerId` → `SingerID` → `singer_id_new` → `encode_singer_id` → `singerId` → `authorId` |
| name 键 | `name` → `author_name` → `SingerName` → `singername` → `singer_name` → `singerName` → `authorName` |
| 头像键 | `sizable_avatar` → `avatar`（经 `normalizeImageUrl`） |
| 丢弃规则 | id 或 name 为空则跳过；**按 id 去重**（同 id 只保留首次） |
| 兜底 | 结果为空且传入 `fallbackName` 时，按 `\s*[/、,，&]\s*` 切分生成 `ArtistRef(id: '', name: 片段)` |

> 坑：兜底生成的 `ArtistRef.id` 是空串，`Song.fromArtistAudio` 依赖「全部 id 为空」这一条件才回填传入的 `artistId`（`music_models.dart:578-583`）。

| `fromFm` | `:611` | `album_audio_id`→`audio_id`→`sid`→`hash` | 先按 `\s[-–—]\s` 拆 `audio_name`/`songname`/`name` 的 title 段 | `hash`→`FileHash`→`320hash`→`hash_320`→`hash_flac` | `time`(毫秒)→`320time`(毫秒)→`timelen`(毫秒)→`timelength`(毫秒) | `trans_param.union_cover`→`sizable_cover`→`cover`→`imgurl` |
| `fromAlbum` | `:664` | `audio_info.hash`→`base.album_id`→`id` | `base.audio_name` | `audio_info.hash` | `audio_info.duration`(毫秒) | `album_info.cover` |
| `fromCache` | `:719` | `id` | `title` | `hash` | `durationMs`(毫秒) | `coverUrl` |

工厂差异要点：

- `fromAlbum` 只认嵌套结构 `{base, audio_info, album_info, authors[]}`，`authors[]` 用 `author_id` / `author_name`；name 为空的作者被丢弃（`music_models.dart:668-679`）。
- `fromArtistAudio` 在「传入 `artistId` 且解析出的歌手 id 全为空」时，用单个 `ArtistRef(id: artistId, name: author_name)` 覆盖（`:578-583`）。
- `fromFm` 用私有 `_splitSongDisplayName`（`:913`）按 `\s[-–—]\s` 把「歌手 - 歌名」拆开。
- `fromCache` 读 `source` 时用 `SongSource.values.asNameMap()[sourceName] ?? kugou`（`:743`），**未知枚举名静默回落 kugou**。

`toCache()`（`:702-717`）键：`id`、`title`、`artist`、`hash`、`albumId`、`albumAudioId`、`albumName`、`coverUrl`、`durationMs`、`artists:[{id,name,avatarUrl}]`；条件写入 `isCloudDrive: true`（仅当为真）与 `source: <枚举 name>`（仅当非 kugou）。

`SongSource`（`:415`）：`kugou`（默认）、`netease`、`local`。

## 5. 约束与坑

1. **没有 `toJson` 的模型无法回写**。除 `LoudnessData` / `LyricCandidate` 外，所有类只能单向解析；需要持久化必须自己写 `toCache`。
2. **`toCache` 的键名与 API 键名不同**（camelCase + `durationMs`），且 `Song.toCache` 对默认值做条件省略（`isCloudDrive`、`source`）。手改缓存结构必须同时改 `fromCache`。
3. **`PlayUrl.loudness` 声明可空但恒非空**：`LoudnessData.fromJson` 永远返回实例，判空不能用于「是否有响度数据」，必须用 `isValid` / `canNormalize`（`loudness_data.dart:33-37`）。
4. **`volume` 字段不在 OpenAPI 契约里**：`api.json` 的 `PlayUrlData`（`api.json:9200-9255`）只有 `url`/`hash`/`priv_status`/`err_code`/`status`/`error_code`，没有 `volume`/`volume_gain`/`volume_peak`；`MusicApi.songUrl` 内有专门 `debugPrint` 探测该字段（`music_api.dart:478-486`）。**响度是否可用取决于后端实际返回，不能凭文档断言。**
5. **列表字段「非 List → null」与「非 List → 空列表」两种风格并存**：`MusicCommentItem.images`、`MusicCommentResponse.*` 返回 null；`DailyRecommend.songs`、`FmStation.previewSongs` 返回空列表。UI 判空方式必须按类区分。
6. **`LoginSession.fromJson` 只解析 3 个键**（`userid`/`token`/`t1`），`sessionId`/`nickname`/`avatarUrl` 恒为 null，需要外部注入（`music_api.dart:80-99`）。
7. **`asMap` 返回 `const {}`**：直接对返回值写入会抛 `UnsupportedError`。
8. **`asInt` 不解析小数**：`"12.5"` 与 `12.5` 都得到 null；`CommentSongScore.songScore` 是唯一用 `double.tryParse` 的例外。
9. **`NetEaseSong.toSong()` 合成 hash `ne_<id>`**：该曲目**不能**用于 `/song/url` 取播放地址（网易云仅用于搜索）。
10. **静默丢弃**：所有列表解析都用 `where` 过滤（`hash` 非空、`id` 非空等），条目缺失不报错，只会让列表看起来「少了几条」；`SongPage.rawItemCount` 保留原始条目数正是为此（`music_models.dart:939-944`）。
11. **枚举回落**：`AudioQuality.fromApiValue` 未知值 → `standard`；`Song.fromCache` 未知 `source` → `kugou`。未知值不报错。
12. **`normalizeImageUrl` 默认 size=480**；`QrCodeInfo.imageUrl`、`NetEaseAlbum.picUrl`、`AlbumShopItem.pic` 不经过它。
13. **二维码状态码**（`music_models.dart:1749-1753`，注释与代码一致）：

| status | 含义 | 对应 getter |
|---|---|---|
| 0 | 等待扫码 | `isWaitingForScan` |
| 1 | 已扫码待确认 | `isWaitingForConfirm` |
| 2 | 已过期 | `isExpired` |
| 4 | 登录成功（且 `token` 非空） | `isSuccess` |
| 3 | **代码未定义** | 无 getter（待核实是否存在于服务端） |
