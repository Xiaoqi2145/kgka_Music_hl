# 性能与稳定性基线

## TL;DR

项目**目前没有任何性能埋点、没有任何基准数据、没有 CI 化的性能回归**：`lib/` 中 `Stopwatch` 只有 2 处业务用途（`player_controller.dart:243`、`playback_loudness.dart:72`），且没有任何一处把耗时写进日志。本文定义 8 项可测量指标（冷启动、首屏、页面切换、滚动帧率、内存、APK 体积、崩溃率、网络失败率），给出每项的**测量命令、观测点、建议目标与回归阈值**；其中 **APK 体积已有实测基线（release 58.69 MiB）**，其余 7 项当前值**均为「未采集」**。三个已知缺陷（背景图 0.7s 延迟、`_prune` 计数覆盖、无失败缓存导致 8s 超时）会直接污染页面切换、内存与网络失败率三项指标。

### 2.3 启动路径的串行阻塞点（M-01 归因）

`main()` 在 `runApp()` 之前有 3 个 `await`，逐个串行：

| 顺序 | 调用 | 锚点 | 阻塞内容 |
|---|---|---|---|
| 1 | `WidgetsFlutterBinding.ensureInitialized()` | `main.dart:27` | 引擎初始化 |
| 2 | `await AppConfig.loadCustomBaseUrl()` | `main.dart:28` | `SharedPreferences.getInstance()` |
| 3 | `await AudioService.init(...)` | `main.dart:32-39` | 起前台服务/通知通道 |
| 4 | `await themeController.load()` | `main.dart:42` | `SharedPreferences` 读主题 |
| 5 | `runApp(...)` | `main.dart:44` | 首帧 |

`initState` 中的重活已用 `unawaited` 异步化（`main.dart:98,103`、`_auth.restore()`、`_downloads.initialize()`），**不阻塞首帧**；但第 2、4 步都读 `SharedPreferences`，存在合并为一次读取的空间。

## 4. 已知风险（与既有缺陷对应）

| # | 风险 | 影响的指标 | 事实与锚点 |
|---|---|---|---|
| R-01 | **自定义背景图渲染延迟 ~0.7s** | M-03 | 用户反馈页面切换时延迟约 0.7s；预加载字节、预解码 `ui.Image`、架构分离等方案均未解决，当前方案已全部回退（`theme_controller.dart`、`main.dart` 保持原版）；根因未定，方向为 `Image.file` 缓存键或 Navigator 过渡动画同步问题。登记于 `KA-Music-项目状态.md:166-171` |
| R-02 | **缩略图 `_prune` 计数被扫描快照覆盖** | M-05、M-06、磁盘占用 | `_prune` 用扫描结果覆盖内存计数（`artwork_cache_service.dart:250-251`），扫描期间并发下载的增量被丢弃 → 计数偏小、**上限可能被突破**。登记于 `KA-Music-项目状态.md:96` |
| R-03 | **无失败缓存 → 每个未缓存封面重试一次 8s 连接超时** | M-04、M-05、M-08 | 断网/弱网时，`_download` 的 `connectionTimeout = 8s`（`artwork_cache_service.dart:286`）会为每个未缓存封面各占一个连接，且失败结果**不缓存**，下次解析再试一次。登记于 `KA-Music-项目状态.md:99` |
| R-04 | **淘汰无低水位，达上限后每次新增触发全目录扫描** | M-04 | `_enforceLimit` 在 `_totalBytes > maxCacheBytes` 时调用 `_prune`（`:193-214`），`_prune` 对每个文件做 `length()` + `lastModified()`（2 次 syscall，`:220-235`）；万级文件时有卡顿风险。登记于 `KA-Music-项目状态.md:97` |
| R-05 | **`.part` 残留不计入大小/条目，启动不清理** | 磁盘占用 | `_download` 的临时文件（`:283`）不计入 `_totalBytes`/`_entryCount`；`clearCache` 会删 `.part` 但**不计大小**（`:179-187`）。登记于 `KA-Music-项目状态.md:98` |
| R-06 | **release 构建仍有约 26 处未守卫的 `debugPrint`** | M-04、M-07 | 仅 15 处受 `kDebugMode` 守卫（详见 `../06-质量保障/静态分析与代码规范.md` §1.7） |
| R-07 | **持久化定时器窗口内进程被杀会丢数据** | 稳定性 | 播放缓存 30s（`player_controller.dart:1020`）、会话 800ms（`:1320`）、历史/统计各 5s（`playback_history_service.dart:97`、`playback_stats_service.dart:185`） |
| R-08 | **无 CI / 无 profile 构建 / 无 Baseline Profile** | 全部 | 仓库无 `.github/`、无 `baseline-prof.txt`；性能回归只能靠人工 |
| R-09 | **仅 `arm64-v8a`** | M-06 | `build.gradle.kts:28-30`；体积基线只在单 ABI 下可比 |
| R-10 | **无崩溃上报** | M-07 | 依赖表无任何崩溃上报 SDK（`pubspec.yaml:9-21`） |
| R-11 | **release 使用 debug 签名** | 发布合规 | `build.gradle.kts:37` |
