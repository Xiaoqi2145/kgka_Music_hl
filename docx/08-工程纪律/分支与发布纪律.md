# 分支与发布纪律

## TL;DR

当前仓库是 master 单主干、125 次提交、origin + upstream 双远程，尚未形成自动化发布链。正式发布必须经过门禁、签名、版本号、冒烟、更新日志、标签六道检查；单人维护可以小改动直提 master，但涉及播放、缓存、鉴权、原生、存储契约的改动必须走临时分支并自审。

## 1. 当前事实与目标

| 项 | 当前事实 | 目标纪律 |
|---|---|---|
| 主分支 | master | master 只接受可发布状态 |
| 长期分支 | 无 | 不建立长期开发分支 |
| 远程 | origin + upstream | 明确推送目标，禁止误推 upstream |
| CI | 无 .github/ | M1 接入 CI，过门禁后才能合并 |
| release 签名 | 使用 debug 签名 | 改为 release 签名，密钥不入库 |
| 系统版本号 | APK 实测 versionCode=1 | 与 AppConfig.appVersionCode=220 对齐 |
| ABI | 配置声明 arm64-v8a，产物实测含多 ABI | 构建配置与产物必须对拍 |

## 2. 分支命名

| 类型 | 命名 | 生命周期 | 合并目标 |
|---|---|---|---|
| 功能 | feat/简短主题 | 一个任务或一个 PR | master |
| 缺陷 | fix/缺陷编号-主题 | 修复并回归后删除 | master |
| 重构 | refactor/模块 | 单一重构目标 | master |
| 发布 | release/vX.Y.Z | 冻结期至发布完成 | master |
| 热修复 | hotfix/vX.Y.Z-主题 | 线上问题关闭后删除 | master |
| 文档 | docs/主题 | 文档改动较大时 | master |

规则：分支名只用小写英文、数字、短横线和斜杠；不使用空格；一个分支不同时承载新功能和无关格式化。

## 3. 单人维护期例外

| 场景 | 是否允许直接提交 master | 补偿措施 |
|---|---|---|
| README 或纯文字小改 | 允许 | 提交前运行文档检查器 |
| 单文件 typo / 注释 | 允许 | 自审 diff，提交信息使用 docs |
| 业务逻辑 | 不建议 | feat/fix 分支 + 本地门禁 + 24 小时自审 |
| 播放、缓存、鉴权、原生 | 禁止直提 | 分支 + 方案 + 测试 + 回滚点 |
| release / hotfix | 禁止无记录直提 | release/hotfix 分支 + 发布模板 |

## 4. 发布流程

1. 关闭本迭代未完成任务，更新 WBS 状态。
2. 确认所有 P0/P1 缺陷已关闭或有负责人和豁免记录。
3. 运行 node docx/tools/check-docs.js。
4. 运行 flutter analyze、dart format --set-exit-if-changed .、flutter test。
5. 核对 pubspec.yaml、AppConfig.appVersion、AppConfig.appVersionCode、APK versionCode。
6. 核对签名证书、applicationId、ABI、权限和包体积。
7. 执行发布冒烟清单，至少覆盖登录、首页、搜索、播放、歌词、下载、缓存、设置。
8. 生成 release APK，保存 SHA-256、构建时间、Git commit。
9. 更新 update.md、版本历史文档和路线图。
10. 创建带注释的 Git tag：git tag -a vX.Y.Z -m “KA Music vX.Y.Z”。
11. 推送分支、tag 和发布说明；发布后观察日志与用户反馈。

## 5. 冻结、灰度与回滚

| 阶段 | 规则 |
|---|---|
| 功能冻结 | 发布前至少 2 个工作日，不再合入非阻塞功能 |
| 代码冻结 | 发布前 1 个工作日，只允许 P0/P1 修复 |
| 灰度 | 先在内部设备安装，确认签名、升级、播放、通知栏 |
| 回滚 | 保留上一版 APK、commit、签名信息和数据库/缓存迁移说明 |
| 热修复 | hotfix 分支只处理一个线上问题，必须补回归用例并合回 master |

## 6. 版本规则

| 项 | 规则 |
|---|---|
| 主版本 | 不兼容存储/API/平台变更 |
| 次版本 | 新增向后兼容功能 |
| 修订版本 | 缺陷修复、文档、性能 |
| versionName | pubspec.yaml 的 X.Y.Z |
| versionCode | 正整数，发布时单调递增；必须实际写入 APK |
| 标签 | vX.Y.Z，与 update.md 条目一一对应 |

## 7. 约束与坑

- release 当前使用 debug 签名，不能视为正式发布配置。
- buildKey.keystore 已被 Git 跟踪，任何公开仓库都应视为已泄露并安排轮换。
- Git 标签 v2.3.0/v2.5.0 与 update.md 不对齐，不能直接据标签推断发布内容。
- APK 系统 versionCode=1 与应用内 220 脱节，升级判断可能异常。
- 多 ABI 实测与 abiFilters 声明不一致，发布前必须解包核验。
