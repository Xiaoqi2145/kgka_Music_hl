# 测试与质量门禁

## TL;DR

当前有 7 个测试文件、52 个用例，flutter test 全通过；行覆盖率 23.76%，且 flutter analyze 因 11 条 info 和默认 fatal-infos 退出码为 1。质量门禁分为提交前、合并前、发布前三层；没有 CI 时必须用本地脚本模拟，任何门禁失败都不能以“先合并再修”作为默认处理。

## 1. 三层门禁

| 门禁 | 时机 | 必跑命令 | 通过标准 |
|---|---|---|---|
| 提交前 | git commit 前 | dart format --set-exit-if-changed .；flutter analyze；受影响 flutter test | 格式无差异；无 error；受影响测试全绿 |
| 合并前 | PR/自审完成前 | 全量 format、analyze、flutter test、node docx/tools/check-docs.js | 全部退出码 0；文档契约已更新 |
| 发布前 | 构建前与构建后 | 全量门禁、flutter build apk --release、冒烟清单、APK 核验 | release 可构建、签名正确、冒烟 100% |

## 2. 本地门禁脚本草案

将以下内容保存为 scripts/check.ps1；脚本必须在任一命令失败时返回非 0：

    $ErrorActionPreference = 'Stop'
    $failed = $false
    function Run-Step($name, $command) {
      Write-Host "[CHECK] $name"
      Invoke-Expression $command
      if ($LASTEXITCODE -ne 0) { $script:failed = $true; Write-Error "FAILED: $name" }
    }
    Run-Step 'format' 'dart format --set-exit-if-changed .'
    Run-Step 'analyze' 'flutter analyze'
    Run-Step 'test' 'flutter test'
    Run-Step 'docs' 'node docx/tools/check-docs.js'
    if ($failed) { exit 1 }
    Write-Host '[PASS] all quality gates passed'
    exit 0

当前 analyze 仍会因 11 条 info 失败；在清零前不得用 --no-fatal-infos 掩盖问题。若临时采用 --no-fatal-infos，必须在 CI 记录为过渡方案，并绑定 TD-66。

## 3. 测试要求

| 改动类型 | 最低要求 | 可豁免条件 |
|---|---|---|
| 纯文档 | 文档健康检查 | 无 |
| 纯样式 | flutter analyze + 手工截图 | 不改变状态/交互 |
| 纯函数 | 新增边界单测 | 可证明已有测试覆盖全部分支 |
| API/模型 | 正常、缺字段、错误类型各一例 | 仅改注释可豁免 |
| 缓存/下载 | 命中、未命中、并发、失败、清理 | 不可豁免 |
| 播放/歌词 | 状态转移、竞态、失败降级、回归用例 | 不可豁免 |
| 原生通道 | 正常返回、平台不支持、异常返回 | 无对应平台时需记录待验证 |
| 存储迁移 | 新旧格式、重复执行、迁移失败 | 不可豁免 |

## 4. 覆盖率策略

| 阶段 | 目标 | 说明 |
|---|---|---|
| 当前 | 23.76%（分母仅含被 import 的 20 个文件） | 作为基线，不等同全项目覆盖 |
| M1 | ≥30% | 先覆盖 ApiClient、缓存、播放核心、认证 |
| M2 | ≥40% | 拆分后每个控制器有独立测试 |
| M4 | ≥50% | 播放状态机、错误恢复、音量均衡 |

覆盖率下降超过 3 个百分点，或关键模块新增逻辑无测试，PR 必须阻塞。

## 5. 例外审批

例外记录至少包含：任务/缺陷编号、跳过的门禁、原因、风险、补做日期、责任人、回滚方式。单人维护也必须在 PR 描述或提交正文留下记录，不接受口头例外。

## 6. 约束与坑

- flutter analyze 当前退出码为 1，不能假设“没有 error 就等于通过”。
- 覆盖率分母不是全仓库，不能把 23.76% 宣传为全项目覆盖率。
- flutter test 通过不代表登录、播放、下载、原生通道和 UI 集成通过。
- Android release 构建必须额外核验 versionCode、签名、ABI 和权限。
- 门禁命令必须在项目根目录运行，避免相对路径误判。
