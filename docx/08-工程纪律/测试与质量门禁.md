# 测试与质量门禁

## TL;DR

质量门禁分为提交前、合并前、发布前三层；没有 CI 时必须用本地脚本模拟，任何门禁失败都不能以「先合并再修」作为默认处理。**测试规模与覆盖率不在此维护**，见 `docx/06-质量保障/测试策略与现有用例.md`；静态分析基线与退出码行为见 `docx/06-质量保障/静态分析与代码规范.md`。

## 1. 三层门禁

> 静态分析一律用 `flutter analyze --no-fatal-infos`：裸 `flutter analyze` 默认 `--fatal-infos` 为 on，当前存在 info 即退出码非 0，作为门禁**永远无法通过**（与 §6 一致）。

| 门禁 | 时机 | 必跑命令 | 通过标准 |
|---|---|---|---|
| 提交前 | git commit 前 | `dart format --set-exit-if-changed lib test`；`flutter analyze --no-fatal-infos`；受影响模块 `flutter test` | 格式无差异；无 error；受影响测试全绿 |
| 合并前 | 自审完成前 | 全量 format、`flutter analyze --no-fatal-infos`、`flutter test`、`node docx/tools/check-docs.js` | 全部退出码 0；文档契约已更新 |
| 发布前 | 构建前与构建后 | 全量门禁、`flutter build apk --release`、冒烟清单、APK 核验 | release 可构建、签名正确、冒烟 100% |

## 2. 本地门禁脚本草案

`scripts/check.ps1` 尚未落地。以下草案**尚未验证**（`scripts/` 目录不存在），落地前不要当作可用门禁：

    $ErrorActionPreference = 'Stop'
    $failed = $false
    function Run-Step($name, $command) {
      Write-Host "[CHECK] $name"
      Invoke-Expression $command
      if ($LASTEXITCODE -ne 0) { $script:failed = $true; Write-Error "FAILED: $name" }
    }
    Run-Step 'format' 'dart format --set-exit-if-changed lib test'
    Run-Step 'analyze' 'flutter analyze --no-fatal-infos'
    Run-Step 'test' 'flutter test'
    Run-Step 'docs' 'node docx/tools/check-docs.js'
    if ($failed) { exit 1 }
    Write-Host '[PASS] all quality gates passed'
    exit 0

> 待修（T-M0-05）：`dart format --set-exit-if-changed lib test` 当前退出码 1（4 个文件未格式化：`lib/ui/pages/library_page.dart`、`lib/ui/widgets/listenable_selector.dart`、`test/artwork_and_selector_test.dart`、`test/player_normalization_test.dart`），因此按此草案运行会停在第一步；且 `flutter test` 的退出码在 PowerShell 下不可信（见 §6），脚本应以 stdout 的 `All tests passed!` 判定而非 `$LASTEXITCODE`。

`--no-fatal-infos` 是当前基线下的过渡方案（`TD-66`）；清零 info 后应改回裸 `flutter analyze`（T-M1-02）。

## 3. 测试要求

| 改动类型 | 最低要求 | 可豁免条件 |
|---|---|---|
| 纯文档 | 文档健康检查 | 无 |
| 纯样式 | `flutter analyze --no-fatal-infos` + 手工截图 | 不改变状态/交互 |
| 纯函数 | 新增边界单测 | 可证明已有测试覆盖全部分支 |
| API/模型 | 正常、缺字段、错误类型各一例 | 仅改注释可豁免 |
| 缓存/下载 | 命中、未命中、并发、失败、清理 | 不可豁免 |
| 播放/歌词 | 状态转移、竞态、失败降级、回归用例 | 不可豁免 |
| 原生通道 | 正常返回、平台不支持、异常返回 | 无对应平台时需记录待验证 |
| 存储迁移 | 新旧格式、重复执行、迁移失败 | 不可豁免 |

## 4. 覆盖率策略

当前覆盖率数值与分母口径见 `docx/06-质量保障/测试策略与现有用例.md` §1.4（**本文件不复制该数字**，它随测试扩充变化）。此处只保留目标：

| 阶段 | 目标 | 说明 |
|---|---|---|
| 当前 | 以 `docx/06-质量保障/测试策略与现有用例.md` §1.4 为准 | 作为基线，不等同全项目覆盖 |
| M1 | ≥30% | 先覆盖 ApiClient、缓存、播放核心、认证 |
| M2 | ≥40% | 拆分后每个控制器有独立测试 |
| M4 | ≥50% | 播放状态机、错误恢复、音量均衡 |

覆盖率下降超过 3 个百分点，或关键模块新增逻辑无测试，必须阻塞合并。

例外记录至少包含：任务/缺陷编号、跳过的门禁、原因、风险、补做日期、责任人、回滚方式。单人维护也必须提交正文留下记录，不接受口头例外。

## 6. 约束与坑

- `flutter analyze` 裸命令因 `--fatal-infos` 默认 on 而退出码非 0；门禁必须显式用 `--no-fatal-infos`，不能假设「没有 error 就等于通过」。
- 覆盖率分母不是全仓库，不能把该数字宣传为全项目覆盖率。
- `flutter test` 通过不代表登录、播放、下载、原生通道和 UI 集成通过。
- PowerShell 下 `flutter test` 的退出码不可信（stderr 的资源提示被记为 `NativeCommandError`），以 stdout 的 `All tests passed!` 判定。
- `dart format --set-exit-if-changed lib test` 当前退出码 1（4 个文件未格式化），门禁脚本落地前需先清零。
- Android release 构建必须额外核验 versionCode、签名、ABI 和权限。
- 门禁命令必须在项目根目录运行，避免相对路径误判。
