# 权限与清单配置

## TL;DR

- Android 侧共声明 **8 条权限**，其中**没有一条是运行时「危险权限」**（无相机、存储、麦克风、通知权限），因此代码里也不存在 `requestPermissions` 流程；真正需要用户交互的是两个「特殊/受限权限」：悬浮窗（`SYSTEM_ALERT_WINDOW`）与安装未知应用（`REQUEST_INSTALL_PACKAGES`）。
- 组件声明共 **5 个自建项**（1 Activity + 2 Service + 1 Receiver + 1 FileProvider），另有 5 个由插件合并进来的组件；自建项的 `exported` 与前台服务类型均已显式声明。
- iOS / macOS 的权限项**基本为空**（无任何 `NS*UsageDescription`、无 `UIBackgroundModes`、macOS 沙箱缺网络与用户选择文件 entitlement），桌面端与 iOS 端的功能缺口大多源于此。

## 3. 危险权限的申请时机与降级行为

**本项目未声明任何 Android 运行时危险权限**，因此不存在「首次进入某页面弹权限框」的流程。两条需要用户交互的路径如下：

| 权限 | 检查方法 | 跳转目标 | 返回后是否复查 | 降级行为 |
|---|---|---|---|---|
| `SYSTEM_ALERT_WINDOW` | `Settings.canDrawOverlays(this)`（`MainActivity.kt:180`） | `Settings.ACTION_MANAGE_OVERLAY_PERMISSION` + `package:$packageName`（`MainActivity.kt:183-187`） | 是：下次开启开关时再次 `checkPermission`（`player_controller.dart:2085`） | 开关回滚为 `false` 并提示；已在显示的悬浮窗由 `hide` 关闭 |
| `REQUEST_INSTALL_PACKAGES` | `packageManager.canRequestPackageInstalls()`（API 26+，`MainActivity.kt:454-456`） | `Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES` + `package:$packageName`（`MainActivity.kt:457-462`） | 否：本次安装流程直接 return，需用户重新点「立即更新」 | 更新流程静默中止，Dart 侧无回调（`app_update_widgets.dart:118-134` 只提示「更新包下载中」） |

## 10. 约束与坑

1. **没有运行时危险权限，也没有权限申请框架**。一旦引入相册以外的危险权限（如 `READ_MEDIA_AUDIO`），必须同时引入 `permission_handler` 或自建通道，并补申请/拒绝/引导流程。
2. **`POST_NOTIFICATIONS` 未声明**：Android 13+ 上桌面歌词通知与媒体通知的可见性**待核实**（清单 8 条权限中无此项，代码无申请）。
3. **本地音乐扫描缺存储权限**：清单无存储/媒体读取权限，扫描用 `dart:io`（`local_music_controller.dart:51-66`），Android 10+ 分区存储下能否读到用户选择的目录**待核实**；若不可读，需要改用 SAF 持久化 URI 或申请媒体权限。
4. **`usesCleartextTraffic="true"`**（`AndroidManifest.xml:15`）允许明文 HTTP；默认 API 地址是 HTTPS，但用户自定义 Base URL 时可能降级为明文，存在风险。
5. **`REQUEST_INSTALL_PACKAGES` 是受限权限**，Google Play 对非应用商店类应用会要求说明；国内商店亦有各自规则。
6. **安装未知应用授权后不会自动继续**：代码在未授权时 return，用户授权后需重新点击更新（`MainActivity.kt:454-464`）。
7. **FileProvider 路径与下载目录强耦合**：改下载目录必须同步改 `update_file_paths.xml`（§6）。
8. **release 使用 debug 签名**（`android/app/build.gradle.kts:33-39`），无法用于正式分发；也影响 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` 之类的签名级权限语义。
9. **iOS/macOS 权限项与沙箱能力基本为空**，两平台的功能缺口主要来自这里，不是 Dart 代码。
10. **桌面端没有权限体系**，但 macOS 沙箱缺 `network.client` 会导致网络请求被拒；这与「权限」在 Android 上的含义不同，容易被忽略。
11. **`ACCESS_NETWORK_STATE` 来自插件合并**，来源**待核实**；若未来移除对应插件，该权限会自动消失。
