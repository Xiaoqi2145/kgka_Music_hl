# 多平台差异矩阵

## TL;DR

- **当前主力平台是 Android**，全部自建原生能力（均衡器、低音增强、桌面歌词、应用内更新、屏幕常亮）都只有 Android 实现。
- iOS / macOS 的插件已注册但**没有任何自建原生代码**，且清单/沙箱配置不完整（缺 `UIBackgroundModes`、缺网络客户端与用户选择文件权限）；Windows / Linux **缺少 `just_audio` 平台实现，播放链路不可用**。
- 除 Android 外的一切格子，判定依据都是「代码里的平台判定 + 插件声明的平台」，**没有真机实测记录，一律标注「未验证」而非「支持」**。

## 7. 约束与坑

1. **「未验证」不等于「可用」**。iOS / macOS / Web 都有插件实现，但本项目从未在此平台跑通完整链路，文档不得写成「支持」。
2. **Windows / Linux 播放不可用**是结构性缺陷：缺 `just_audio` 平台实现，而不是配置问题；桌面端要可用必须引入 `just_audio_windows` / `just_audio_linux` 或换引擎。
3. **macOS 沙箱配置不完整**（缺网络客户端与用户选择文件权限），即使加了桌面播放实现，网络与文件功能仍会被系统拒绝。
4. **iOS 权限项缺失**：`Info.plist` 无 `NSPhotoLibraryUsageDescription`，相册选图会触发系统终止；无 `UIBackgroundModes`，后台播放不生效。
5. **Bundle ID 仍是模板值** `com.example.kgkaMusicHl`（iOS 与 macOS），发布前必须替换。
6. **Web 页面描述与窗口标题仍是模板值**（`A new Flutter project.`、`kgka_music_hl`）。
7. **Android 存储权限缺口**：清单未声明存储/媒体权限，本地音乐扫描在 Android 10+ 分区存储下能否读到文件**待核实**（详见 KA-05-03 §7）。
8. **「扫码登录」不含相机能力**，不需要相机权限；二维码由服务端生成，客户端只负责渲染与轮询状态。
9. **音量均衡在非 Android 平台只能衰减不能提升**（提升路径硬性要求 Android 原生 `LoudnessEnhancer`）。
10. **平台判定分散在 9 个文件 13 处**，新增平台时需要逐处检查，没有统一的 `PlatformSupport` 抽象。
