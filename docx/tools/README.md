# 知识库工具

## TL;DR

`docx/tools/check-docs.js` 是知识库的健康度检查器，一条命令校验 **元信息完整性、必备章节、编号唯一性、链接有效性、README 索引完整性**。它是 `07-推进计划/任务分解-WBS.md` 中 T-M7-05「文档健康度机制」的落地物，建议在每次改文档后执行。

---

## 1. 用法

```powershell
# 在项目根目录执行
node docx\tools\check-docs.js

# 退出码：0 = 全部通过；1 = 存在问题
echo $LASTEXITCODE
```

---

## 2. 检查项

| 编号 | 检查项 | 规则 | 失败示例 |
|---|---|---|---|
| CH-01 | 元信息完整性 | 每篇文档（除自动生成物）必须含 `文档编号：`、`级别：`、`状态：`、`关联代码：`、`最近更新：`、`变更触发条件：` | `META  xx.md 缺少「关联代码：」` |
| CH-02 | 必备章节 | 必须含 `TL;DR`、`约束与坑`、`待办` 三段（索引与术语表、脚本生成物豁免） | `SECT xx.md 缺少章节「约束与坑」` |
| CH-03 | 编号唯一性 | `> 文档编号：` 全局唯一，不重复 | `DUP  a.md 编号 KA-03-03 与 b.md 重复` |
| CH-04 | 链接有效性 | 相对链接必须指向存在的文件或非空目录；已剥离代码块与行内代码，避免正则误报 | `LINK xx.md -> yyy.md 不存在` |
| CH-05 | 索引完整性 | 每篇文档的 basename 必须出现在 `docx/README.md` 中 | `IDX  xx.md 未在 README 索引中登记` |

## 3. 维护规则

| 规则 | 说明 |
|---|---|
| T-01 | 新增文档后必须先在 `docx/README.md` 的「文档编号总表」分配编号，再写文件头 |
| T-02 | 改文档后执行本脚本；退出码非 0 不得提交（对应 `08-工程纪律/文档与知识管理纪律.md`） |
| T-03 | 脚本豁免清单（`EXEMPT_SECTIONS`）只允许登记索引与自动生成物，不得为逃避检查而豁免 |
| T-04 | 自动生成物（`API-端点清单.md`、`API-Schema索引.md`）由脚本重新生成，禁止手工编辑正文 |

---

## 4. 约束与坑

| 编号 | 约束 | 说明 |
|---|---|---|
| T-05 | 脚本只做**结构**校验，不判断内容正确性 | 内容准确性靠 `08-工程纪律/代码评审清单.md` |
| T-06 | 链接检查忽略外链（http/https/mailto） | 外链有效性需人工确认 |
| T-07 | 编号检查基于文件头声明，不校验编号与目录号是否匹配 | 见 `00-元数据/文档规范与维护约定.md` §3 |
| T-08 | 依赖 Node.js（本机实测 v24.15.0），不依赖任何 npm 包 | 无 `node_modules` |
