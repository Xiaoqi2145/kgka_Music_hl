## 一句话结论（TL;DR）

1. 统一格式为 `type(scope): subject`，**冒号必须是半角 `:`**，subject 用中文祈使句、不超过 50 字、句末不加句号。
2. `type` 只允许 §3.2 表中的 12 个值；`scope` 只允许 §3.3 表中的 21 个值；正文与脚注仅在中大型改动时写，破坏性变更必须写 `BREAKING CHANGE:`。
3. **本模板是目标态，不是现状描述**：实测 125 次提交中 67 次用了全角冒号 `：`，并存在 `fixs`、`flx`、`add`、`remove`、`publish` 等非规范 type（见 §2）；新提交一律按本模板执行，历史提交不追溯改写。

## 2. 可直接复制的模板

### 2.1 精简版（默认，90% 的提交用这个）

```text
<type>(<scope>): <subject>
```

### 2.2 完整版（中大型改动）

```text
<type>(<scope>): <subject>

为什么改：
- <问题现状 / 触发条件>

改了什么：
- <按模块列要点，每条一行>

影响与验证：
- <受影响的页面/平台>
- <执行过的验证命令或手工步骤>

关联：<TD-xx / T-Mx-xx / KA-BUG-YYYYMMDD-nn / RC-xx>
```

### 2.3 破坏性变更（必须写脚注）

```text
<type>(<scope>): <subject>

<正文>

BREAKING CHANGE: <不兼容点 + 迁移方式>
关联：<编号>
```

### 2.4 发版提交（固定格式）

```text
chore(release): 2.3.0

- pubspec.yaml: 2.3.0+230
- AppConfig.appVersion / appVersionCode 同步
- update.md 新增 v2.3.0 条目
```

## 3. 逐字段规则

### 3.1 subject 规则

| 规则 | 要求 | 反例 |
|---|---|---|
| 语言 | 中文（代码标识符保留英文原样） | `fixed the bug` |
| 语态 | 祈使句，描述「做了什么」 | `修复了…的问题了` |
| 长度 | ≤ 50 字（含 scope 前缀整行 ≤ 72 字符） | 113 字符的长句（历史最长值） |
| 标点 | 句末不加句号；不在句中用全角冒号 | `feat：播放页` |
| 粒度 | 一次提交只做一件事 | 一个提交同时拆文件 + 改逻辑 + 改文档 |
| 禁止 | 「例行提交」「优化」「修复已知问题」等无信息量描述 | `feat：例行提交`（历史真实存在） |

### 3.2 type 取值表（12 个，不可自创）

| type | 含义 | 何时用 | 何时不用 |
|---|---|---|---|
| `feat` | 新增用户可见功能 | 新增页面、设置项、能力 | 仅改内部实现 |
| `fix` | 修复缺陷 | 修复可复现的错误行为 | 重构但行为不变 |
| `refactor` | 重构，行为不变 | 拆文件、抽类、改命名 | 顺带改了行为 |
| `perf` | 性能优化 | 冷启动、滚动、解码、体积 | 功能改动 |
| `docs` | 文档 | `docx/`、`README.md`、`update.md`、代码注释 | 代码行为变更 |
| `test` | 测试 | 新增/修改 `test/` 下文件 | 为测试而改产品代码（用 `fix`/`refactor`） |
| `build` | 构建、依赖、打包 | `pubspec.yaml`、Gradle、签名、ABI | CI 配置 |
| `ci` | 持续集成与门禁 | `scripts/*.ps1`、工作流、校验脚本 | 业务代码 |
| `style` | 格式调整，不影响逻辑 | `dart format` 结果、空行 | 任何语义变更 |
| `chore` | 杂项 | 发版、忽略文件、清理临时文件 | 能归入以上任一类时 |
| `revert` | 回滚提交 | `git revert` 生成的提交 | 手工改回去 |
| `deps` | 依赖升降级（本模板自定义） | 仅改版本号、无代码适配 | 依赖升级同时改代码（用 `feat`/`fix`） |

### 3.3 scope 取值表（21 个，与代码目录/模块对齐）

| scope | 对应代码位置（锚点） | 典型改动 |
|---|---|---|
| `config` | `lib/config/app_config.dart` | 常量、TTL、缓存上限、`--dart-define` |
| `core` | `lib/core/api_client.dart` | 重试、超时、session 头 |
| `models` | `lib/models/` | JSON 解析、字段增删 |
| `services` | `lib/services/` | 跨域服务改动 |
| `controllers` | `lib/controllers/` | 跨域控制器改动 |
| `auth` | `lib/controllers/auth_controller.dart`、`lib/ui/pages/login_page.dart` | 登录、登出、会话恢复 |
| `player` | `lib/controllers/player_controller.dart`、`lib/ui/pages/player_page.dart` | 播放、队列、音质、倍速 |
| `lyrics` | `lib/services/music_api.dart`（`parseLyrics`）、`player_page.dart` 歌词区 | 歌词解析、逐字、翻译、桌面歌词 |
| `cache` | `lib/services/cache_service.dart`、`artwork_cache_service.dart` | 数据缓存、缩略图缓存、淘汰 |
| `download` | `lib/services/download_service.dart`、`lib/controllers/download_controller.dart` | 下载、断点续传 |
| `local` | `lib/controllers/local_music_controller.dart`、`lib/ui/pages/local_songs_page.dart` | 本地音乐扫描 |
| `theme` | `lib/controllers/theme_controller.dart`、`lib/ui/app_theme.dart` | 配色、深色、背景图 |
| `settings` | `lib/ui/pages/settings_page.dart` | 设置页入口与分组 |
| `home` | `lib/ui/pages/home_page.dart` | 首页、推荐、电台 |
| `search` | `lib/ui/pages/search_page.dart` | 搜索、热搜、历史 |
| `playlist` | `lib/ui/pages/playlist_detail_page.dart`、`library_page.dart` | 歌单、收藏、排序 |
| `cloud` | `lib/ui/pages/cloud_drive_page.dart` | 云盘 |

> 取值优先级：能落到具体模块就用模块 scope（如 `cache`），跨多模块或无法归类时才用 `services` / `controllers` / `ui` 级别。**同一提交只写一个 scope**；确实跨域时取「改动量最大」的那个，其余在正文列出。

### 3.4 正文与脚注规则

| 区块 | 何时必须写 | 格式要求 |
|---|---|---|
| 正文 | 改动涉及 ≥ 2 个文件或 ≥ 30 行；或修复的是线上缺陷 | 分「为什么改 / 改了什么 / 影响与验证」三段；每行 ≤ 72 字符 |
| `关联：` 行 | 关联台账或任务时 | 用台账编号：`TD-xx`、`T-Mx-xx`、`C-xx`、`K-xx`、`A-xx`、`RC-xx`、`KA-BUG-YYYYMMDD-nn` |
| `BREAKING CHANGE:` | 改了公开 API、存储键、数据格式、包名/签名 | 必须写明「不兼容点 + 迁移方式」，否则视为未完成 |
| `Closes #N` | 关联 Issue/PR | 固定英文写法，GitHub 才会自动关闭 |

### 4.1 一条完整多行提交（复制后改内容）

```text
fix(cache): 修正缩略图缓存计数漂移导致上限被突破

为什么改：
- _prune 用扫描开始时的目录快照覆盖内存计数，扫描期间并发下载的增量被丢弃
- 计数偏小 → 512MB 上限可被突破，磁盘占用不受控

改了什么：
- _prune 改为按删除量扣减（_totalBytes -= removedBytes）
- _entryCount 同步按删除条目数扣减

影响与验证：
- 影响：设置页缓存管理显示的占用大小；不影响缓存命中与读取
- 验证：flutter test test/artwork_cache_lru_test.dart；新增并发写入用例通过

关联：TD-01、T-M3-02、G-02
```

## 5. 写法：命令行与编辑器

### 5.1 单行提交

```powershell
git add -A
git commit -m "fix(cache): 修正缩略图缓存计数漂移"
```

### 5.2 多行提交（PowerShell here-string，推荐）

```powershell
$msg = @'
fix(cache): 修正缩略图缓存计数漂移导致上限被突破

为什么改：
- _prune 用扫描快照覆盖计数，并发下载增量被丢弃

改了什么：
- 改为按删除量扣减

关联：TD-01、T-M3-02
'@
git commit -m $msg
```

| 要点 | 说明 |
|---|---|
| 用单引号 here-string `@'…'@` | 内部 `$` 与反引号不会被展开；`'@` 必须顶格 |
| 不要用双引号 here-string `@"…"@` | 正文若含 `$` 会被 PowerShell 变量替换 |
| 换行必须是 LF 或 CRLF 均可 | Git 提交信息本身不做行尾规范化 |

### 5.3 多行提交（`-m` 分段，适合两段式）

```powershell
git commit -m "fix(cache): 修正缩略图缓存计数漂移" -m "改为按删除量扣减；关联 TD-01、T-M3-02"
```

> 每个 `-m` 生成一个段落，段落之间自动空行。

### 5.4 编辑器提交

| 动作 | 命令 | 说明 |
|---|---|---|
| 打开默认编辑器写完整信息 | `git commit` | 编辑器由 `core.editor` 决定 |
| 边看 diff 边写 | `git commit -v` | 编辑器底部附完整 diff，`#` 开头的行不进入提交信息 |
| 从文件读取 | `git commit -F .git/COMMIT_MSG.txt` | 适合脚本化 |
| 设置模板（推荐一次配置） | `git config commit.template .gitmessage` | 每次 `git commit` 预填 §2.2 的骨架 |

### 5.5 改错后的补救

| 场景 | 命令 | 注意 |
|---|---|---|
| 刚提交、未推送 | `git commit --amend -m "新的信息"` | 会改写提交哈希 |
| 已推送到 `origin/master` | 不 amend，改为追加一次 `docs`/`chore` 提交说明 | 避免强制推送污染他人历史 |
| 想撤销提交但保留改动 | `git reset --soft HEAD~1` | 改动回到暂存区 |

## 6. 约束与坑

| # | 约束/坑 | 影响 | 核对锚点 |
|---|---|---|---|
| 1 | **全角冒号 `：` 不会被任何工具识别**。历史 67 次提交用了全角冒号，导致按 `^feat:` 过滤时漏掉一半历史。 | 无法用脚本统计与生成 changelog | §1 实测 |
| 2 | `fixs`、`flx` 是拼写错误，语义仍为 `fix`；不要因为「历史都这么写」而继续沿用。 | type 统计失真 | §1.1 |
| 3 | `publish：X.Y.Z` 是历史发版写法，与 SemVer 标签 `vX.Y.Z` 不同步（标签有 `v2.3.0`/`v2.5.0`，`update.md` 无对应条目）。发版统一改用 `chore(release): X.Y.Z` 并同步打标签。 | 版本历史不可信 | `../01-项目总览/构建与发布流程.md` §7 K-05 |
| 4 | 合并提交由 GitHub 生成，不要手写 `Merge pull request …`；本地同步用 `git pull --rebase` 减少噪音。 | 历史可读性 | `git log --merges` |
| 5 | 目前**没有提交信息校验脚本**（`scripts/` 目录不存在），规则靠自觉；接入 CI 前不得声称「已强制」。 | 规则可能被绕过 | `../07-推进计划/任务分解-WBS.md` T-M0-05 |
| 6 | 一次提交只做一件事（`../07-推进计划/工程化推进总纲.md` P-03）。历史存在「一个提交含 5 个 `feat：`」的记录，无法独立回滚。 | 回滚粒度失效 | `git log` 历史 |
| 7 | 文档与代码同提交（规范 D-08）。触及 `04-`/`05-` 契约时必须同提交更新。 | 文档静默腐烂 | `../00-元数据/文档规范与维护约定.md` §5 |
