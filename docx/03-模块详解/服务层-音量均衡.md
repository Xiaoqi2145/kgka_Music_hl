# 服务层-音量均衡

## 1. 一句话结论（TL;DR）

音量均衡是**纯前馈控制系统**：以曲目 LUFS 为测量输入、用户配置的参考 LUFS 为参考输入，算出线性增益后走双路径执行——`gainDb > 0.5` 交给 Android `LoudnessEnhancer`，`gainDb < -0.5` 交给 `just_audio.setVolume`，其余旁路（lib/services/volume_normalization_service.dart:99-191）。

数据来源是 `/song/url` 响应里的 `volume` / `volume_gain` / `volume_peak`；**后端未透传时静默旁路**（增益按 1.0 处理，不报错、不阻塞播放），可通过 `adb logcat` 过滤 `[VolumeNorm]` 与 `[KA Music][loudness]` 验证。

## 3. 设计说明与细节

### 3.1 computeGainLinear 逐步推导

`computeGainLinear(LoudnessData?)`（lib/services/volume_normalization_service.dart:68-90）：

| 步 | 条件 | 运算 | 单位/范围 |
|---|---|---|---|
| 1 | `data == null` 或 `!data.isValid` | 返回 `null`（调用方旁路） | — |
| 2 | 恒成立 | `gain = 10^((referenceLufs - lufs) / 20)` | 线性倍数 |
| 3 | `gain != null && isFinite && != 0.0`（指服务端 dB 字段） | `gain *= 10^(data.gain / 20)` | 线性倍数 |
| 4 | `peak != null && isFinite && peak > 0 && peak <= 4.0` | `gain = min(gain, 0.95 / peak)` | 峰值限制，留 5% 余量 |
| 5 | 恒成立 | `return gain.clamp(0.1, 3.0)` | 饱和限幅 |

`computeGainDb(LoudnessData?)`（:93-97）：`20 * log10(linear)`，线性为 null 时返回 null。

数值示例（与测试一致）：`lufs = -8`、`referenceLufs = -14`、无 `gain`/`peak` → `10^((-14+8)/20) = 10^(-0.3) ≈ 0.501187`（test/volume_normalization_service_test.dart:37-43）。

### 3.2 双路径策略

`_applyForTrack`（lib/services/volume_normalization_service.dart:131-191）的分支：

| 条件 | 路径 | 执行动作 | 返回值 |
|---|---|---|---|
| `!enabled` | 禁用 | `disableLoudnessEnhancer` | 1.0 |
| `gainLinear == null`（LUFS 缺失/非法） | 旁路 | `disableLoudnessEnhancer` | 1.0 |
| `gainDb > 0.5` 且 Android 且 `audioSessionId > 0` | 提升（boost） | `enableLoudnessEnhancer({audioSessionId, gainMillibels})`，毫贝 = `(gainDb * 100).round().clamp(0, 3000)` | `gainLinear` |
| `gainDb > 0.5` 但非 Android 或会话无效 | 旁路 | `disableLoudnessEnhancer` | 1.0 |
| `gainDb > 0.5` 但原生调用抛异常 | 旁路 | `disableLoudnessEnhancer` | 1.0 |
| `-0.5 <= gainDb <= 0.5` | 旁路 | `disableLoudnessEnhancer` | 1.0 |
| `gainDb < -0.5` | 衰减（attenuate） | 只 `disableLoudnessEnhancer`；实际音量由控制器用 `setVolume` 施加 | `gainLinear` |

控制器侧据此决定播放器音量（lib/controllers/player_controller.dart:2406-2410）：

```dart
_normalizationVolume =
    _volNormService.enabled && loudness != null && gainLinear < 1.0
    ? gainLinear
    : 1.0;
```

即：**提升路径不改播放器音量**（交给原生增强器），**衰减路径把 `gainLinear` 作为播放器音量**。最终音量 = `_normalizationVolume * (闪避中 ? 0.5 : 1.0)`（:240-241）。

### 3.3 LoudnessLookup：有界缓存与窗口

`LoudnessLookup`（lib/services/playback_loudness.dart:6）字段：

| 字段 | 类型 | 说明 | 锚点 |
|---|---|---|---|
| `_cache` | `Map<String, LoudnessData>` | 仅存 `canNormalize == true` 的结果 | :10、:26-30 |
| `_pending` | `Map<String, Future<LoudnessData?>>` | 同键请求合并（coalescing） | :11、:38-39 |
| `_retryAfter` | `Map<String, DateTime>` | 失败/缺数据的回退窗口 | :12、:49、:55 |
| `_retainedKeys` | `Set<String>?` | 当前播放窗口的键集合，null 表示不限 | :13 |
| `_now` | `DateTime Function()` | 可注入时钟（测试用） | :7-9 |

| 方法 | 行为 | 锚点 |
|---|---|---|
| `retainKeys(Set<String>)` | 记录窗口并**立即**清理窗口外的 `_cache` 与 `_retryAfter` | :16-20 |
| `_canRetain(key)` | `_retainedKeys` 为 null 时恒 true，否则要求包含 | :22 |
| `get(key)` | 读缓存 | :24 |
| `put(key, data)` | 窗口外或不可归一化则丢弃；成功则清 `_retryAfter` | :26-30 |
| `resolve(key, fetch)` | 缓存命中 → 直接返回；在途 → 返回同一 Future；回退窗口内 → 返回 null；否则发起 `fetch` | :32-65 |
| 回退窗口 | 缺数据或抛错时 `_retryAfter[key] = now + 1 分钟` | :49、:55 |
| 迟到的完成 | `put` 被 `_canRetain` 拒绝时不入缓存，但**仍把结果返回给调用方**（供持久化） | :44-52（test/playback_loudness_test.dart:8-31 验证） |

窗口键由控制器维护：`_loudnessKey(song, quality) = ${source.name}:${hash|id}:${quality.apiValue}`（player_controller.dart:727-728），窗口集合来自「上一首 / 当前 / 下一首」（:709-725）。

### 3.4 PlaybackLoudness：单曲准入窗口

`PlaybackLoudness`（lib/services/playback_loudness.dart:70）：

| 成员 | 值/语义 | 锚点 |
|---|---|---|
| `window` | `const Duration(seconds: 3)` | :75 |
| `generation` | 每次 `begin`/`reopen` 递增 | :76、:94、:119 |
| `key` | 当前曲目+音质的键 | :77 |
| `data` | 已准入的响度数据 | :78 |
| `applicableData` | `_applied` 为真或仍在窗口内时取 `data`，否则 null | :82-87 |
| `begin(sourceKey, initial)` | 开新歌：generation+1、重置窗口与 applied 标记 | :93-99 |
| `startPlayback()` | 首次调用记录窗口起点（`??=`） | :101-103 |
| `accept(sourceKey, expectedGeneration, value)` | 键、代际、有效性、窗口四重校验；通过则写 `data` | :105-115 |
| `markApplied(generation)` | 代际一致时置 `_applied = true` | :89-91 |
| `reopen(cached)` | 设置变更专用：generation+1 并重置窗口起点，不算新歌 | :117-122 |

准入窗口的意义：**加载耗时不计入 3 秒窗口**（`startPlayback` 在 `ready` 后才调用，player_controller.dart:2376-2378），迟到的元数据只进缓存、不污染本次播放（test/playback_loudness_test.dart:35-66）。

## 4. 约束与坑

1. **服务默认值与控制器默认值不一致**（−11 vs −14，见 §2.3），运行期以控制器为准；改动任一处需同步注释。
2. **`canNormalize` 不校验 `gain`/`peak`**：`lufs` 合法但 `peak` 为负或 >4 时，峰值限制分支会被跳过（volume_normalization_service.dart:82-87）。
3. **峰值限制的阈值是 `peak <= 4.0`**：`peak` 超出该范围时不做限制，可能削波。
4. **增益钳位 `[0.1, 3.0]` 会把极端数据静默截断**，日志里的 `gainLinear` 是钳位后的值。
5. **提升路径的毫贝上限是 3000（=30 dB）**，Dart 与 Kotlin 各钳一次（volume_normalization_service.dart:155、MainActivity.kt:487）。
6. **提升路径不改 `audioPlayer.volume`**：若同时用 `LoudnessEnhancer` 与 `setVolume` 提升音量，会双重放大——当前代码用 `gainLinear < 1.0` 严格区分。
7. **衰减路径依赖控制器**：服务只返回线性值并关闭增强器，真正降低音量发生在 `_applyPlaybackVolume()`；绕过控制器直接调服务不会听到衰减。
8. **3 秒准入窗口是硬边界**：`window` 不可配置（`static const`），慢网络下响度只在下次播放生效（日志提示 `metadata cached for later`）。
9. **`retainKeys` 立即清理**：窗口外键被删除，迟到结果只能返回给当次调用方，不会留在缓存（test/playback_loudness_test.dart:19-29）。
10. **失败回退窗口固定 1 分钟**，且缺数据与抛错共用同一窗口（playback_loudness.dart:49、:55）。
11. **`_retryAfter` 不区分错误类型**：后端 4xx 与网络超时同样只等 1 分钟。
12. **设置变更会 `reopen` 而非 `begin`**：换歌与改设置语义不同，前者清空 `data`，后者保留缓存值（:93-99 vs :117-122）。
13. **云盘与网易云永远旁路**（§3.9），用户看到的是「同一首歌换源后响度不一致」。
14. **本模块的日志未加 `kDebugMode` 判断**（对比 lib/services/vip_background_task.dart:90-95 的写法），构建配置不会屏蔽这些打印调用，高频播放时会增加日志量。
