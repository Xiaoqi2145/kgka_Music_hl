# 项目概览与定位

## TL;DR

KA Music 是一个基于 Flutter 的**第三方音乐客户端**，通过第三方 KuGou Music API 获取音乐数据，覆盖搜索、播放、歌词、下载、歌单、云盘、FM 等完整链路；主力平台是 Android，代码规模约 3.07 万行 Dart，采用「分层 + 手动 DI + ChangeNotifier」的原生方案，不引入任何第三方状态管理或路由框架。

## 2. 平台支持

| 平台 | 目录存在 | 实际状态 | 判定依据 |
|---|---|---|---|
| Android | ✅ | **主力平台** | 唯一有原生 Kotlin 实现与权限配置的平台；仅构建 `arm64-v8a` |
| iOS | ✅ | 未验证 | 无 iOS 原生实现；音量均衡的 `LoudnessEnhancer` 仅 Android |
| Windows | ✅ | 未验证 | 桌面歌词走独立服务，桌面端行为未确认 |
| macOS | ✅ | 未验证 | 同上 |
| Linux | ✅ | 未验证 | 同上 |
| Web | ✅ | 未验证 | `dart:io` 在 Web 不可用（缓存、下载、本地音乐均依赖文件系统） |

**结论**：当前可交付平台只有 Android。其余平台属于「脚手架存在但未验证」，涉及 `dart:io` 的功能在 Web 上会直接不可用。

详见 `05-平台与原生/多平台差异矩阵.md`。

## 4. 技术选型与取舍

| 维度 | 选择 | 取舍理由（可从代码反推） | 代价 |
|---|---|---|---|
| 状态管理 | `ChangeNotifier` + `AnimatedBuilder` | 无第三方依赖，学习成本低 | 无选择器，`notifyListeners()` 粒度粗；高频位置更新需另开 `positionListenable` |
| 路由 | Navigator 1.0 | 页面数量可控，无需深链 | 无路由表，跳转散落在 UI；`player_page.dart` 达 3 537 行 |
| 依赖注入 | 构造函数手动注入（`lib/main.dart`） | 显式、可追踪 | 装配点集中，新增依赖需改 `main.dart` |
| 持久化 | `shared_preferences` + 文件系统 | 轻量，无 SQLite 迁移成本 | 大数据量性能差；JSON 全量读写 |
| HTTP | `http`（接口） + `dio`（下载） | `http` 轻量、`dio` 支持下载进度 | 两套 HTTP 栈并存 |
| 音频 | `just_audio` + `audio_service` + `audio_session` | 成熟组合，支持后台与通知栏 | 三库状态需手工同步 |
| 音效 | 自建 MethodChannel（`audio_effects`） | 官方插件不提供 Android 均衡器/LoudnessEnhancer | 仅 Android 可用，需维护 Kotlin |
| 设计 | Material 3 / Material You | 原生支持动态配色 | 部分页面需手工适配大屏 |
| 缓存 | 三套独立实现（数据 / 缩略图 / 播放） | 生命周期与淘汰策略不同 | 接口不统一，设置页需分别管理 |

## 6. 约束与坑

1. **单一后端依赖**：所有数据来自同一后端，无本地降级数据源；后端不可用时 App 只能读缓存。
2. **Web 平台实际不可用**：缓存、下载、本地音乐依赖 `dart:io`。
3. **版本号三处手工同步**，无自动化校验。
4. **无 CI**：所有质量检查靠本地手工执行（见 `08-工程纪律/测试与质量门禁.md`）。
5. **release 使用 debug 签名**（`android/app/build.gradle.kts`），不具备正式分发条件。
6. **仅 arm64-v8a**，不支持 32 位与 x86 设备/模拟器。
7. **主文档 `KA-Music-项目状态.md` 记录时间早于当前版本**（2026-09-08），部分结论需以代码为准。
