## 1. 知识库的目标

本知识库要回答三类问题，缺一不可：

| 类别 | 问题 | 对应目录 |
|---|---|---|
| **是什么（What）** | 这个项目有哪些模块、字段、接口、设置项、平台差异？ | `01-` `03-` `04-` `05-` |
| **为什么（Why）** | 为什么这样分层、这样缓存、这样降级？约束和取舍是什么？ | `02-` `06-` |
| **接下来怎么做（How next）** | 下一版做什么、谁在什么节奏下做、做到什么标准算完成？ | `07-` `08-` `09-` |

**判定标准**：一个从未接触本项目的工程师，只读 `docx/` 就能独立完成「改一个设置项 / 加一个 API / 修一个播放缺陷 / 发一个版本」，且不需要反复追问口头信息。

## 2. 文档分级

| 级别 | 标记 | 含义 | 更新频率 |
|---|---|---|---|
| L0 | 🧭 索引 | 导航与目录，不承载细节 | 每次新增文档时 |
| L1 | 📌 契约 | 接口、数据模型、设置键、平台清单。**改动即失效** | 代码变更同步更新 |
| L2 | 📖 说明 | 架构、模块、数据流。描述「当前设计」 | 架构变更时 |
| L3 | 📋 计划 | 路线图、WBS、排期、风险 | 每迭代 |
| L4 | ⚖️ 纪律 | 规范、流程、门禁、模板 | 每季度回顾 |

## 3. 文件命名与目录约定

1. 目录名：`NN-中文名/`，`NN` 为两位数字，保持排序稳定。
2. 文件名：`中文名.md`；同一目录内文件名不得重复；不使用空格。
3. 一篇文档只讲一件事。**单文档超过 800 行必须拆分**，拆分为 `主题.md` + `主题-子主题.md`。
4. 所有文档使用 UTF-8、LF 换行、Markdown 语法；不使用 HTML 标签（表格用 Markdown 表格，流程图用 mermaid）。
5. 交叉引用使用**相对路径**，形如 `../03-模块详解/服务层-缓存体系.md`；不写绝对路径。

## 4. 文档模板（必须遵守）

每篇 L1–L4 文档的头部必须有：

```markdown
> 文档编号：KA-<目录号>-<序号>
> 级别：L2 📖
> 状态：现行 / 草案 / 待重写 / 已废弃
> 关联代码：lib/xxx/yyy.dart（主） + 其余引用文件
> 最近更新：YYYY-MM-DD
> 变更触发条件：何时必须回来改这篇文档
```

正文推荐结构：

1. **一句话结论**（TL;DR，3 行以内）
2. **现状**（事实，可核对）
3. **设计说明 / 细节**（表、图、代码片段）
4. **约束与坑**（已知限制，必须显式写出）
5. **待办与关联**（指向 `07-` / `06-` 文档）

## 5. 写作纪律（硬性）

| 编号 | 纪律 | 违反后果 |
|---|---|---|
| D-01 | **不得臆造**。凡是代码里没有的行为、字段、默认值，不得写入。无法确认时写「待核实」并登记到 `06-质量保障/已知问题与技术债台账.md`。 | 文档误导 → 返工 |
| D-02 | **可核对**。关键结论必须给出可验证锚点：文件路径、类名、方法名、设置键、行号（如 `lib/core/api_client.dart:95`）。 | 无法评审 |
| D-03 | **写现状，不写愿景**。愿景只能出现在 `07-` 目录。L1/L2 文档描述的是「当前代码的真实行为」。 | 混淆事实与计划 |
| D-04 | **术语统一**。使用 `00-元数据/术语表.md` 的定义，禁止同义词混用（如「缩略图缓存」不得写成「图片缓存」）。 | 检索失效 |
| D-05 | **默认值必须标全**。设置项、常量、上限、TTL 必须写默认值与取值范围。 | 回归误判 |
| D-06 | **显式写出「不做什么」**。例如「有意不缓存首页大卡封面」比「缓存封面」更有价值。 | 需求误读 |
| D-07 | **表格优先**。枚举型内容（字段、设置键、平台差异）一律用表格，不用散文。 | 难以比对 |
| D-08 | **文档与代码同提交**。改动触及 L1 契约时，同一提交内必须更新对应文档。 | 见 `08-工程纪律/文档与知识管理纪律.md` |
| D-09 | **过期标记**。发现文档与代码不一致且暂时无暇修复，必须在头部改 `状态：待重写` 并写明差异点。 | 静默腐烂 |
| D-10 | **不复制大段源码**。引用关键片段（≤30 行），其余用 `文件:方法名` 指路。 | 文档与代码双份维护 |
| D-11 | **行数必须注明口径**。项目行数的**权威口径为 LF 行数（含空行）**，与编辑器、`read` 工具一致；引用「非空行」数字时必须显式标注。当前权威值（2026-09-25 实测）：`lib/`+`test/` = 76 文件 / 36 154 行（非空 33 429）；`player_page.dart` = 3 544（非空 3 298）；`player_controller.dart` = 3 322（非空 3 101）；`test/` = 11 文件 / 2 865 行（非空 2 639）。 | 数字互相矛盾 |
| D-12 | **编号全局唯一**。文档编号由 `docx/README.md` 的「文档编号总表」分配，新增文档前必须先登记；禁止复用已分配编号。 | 引用歧义 |
| D-13 | **头部元信息必须写在文件开头的连续引用块内**，且取值必须真实，不得沿用模板占位符（如 `状态：现行 / 草案 / 待重写 / 已废弃`）。校验脚本会剥离代码块后检查，正文模板示例不能替代头部声明。 | 元信息校验形同虚设 |
| D-14 | **行内代码反引号必须配对**。未配对的反引号会让 Markdown 渲染错位，也会干扰依赖文本扫描的校验脚本。 | 排版错乱、校验误判 |
| D-15 | **行号锚点必须写全文件名**。引用代码位置一律写成 `文件路径:行号`（如 `lib/ui/app_theme.dart:65`）；**禁止跨文件的简写锚点**——即只写 `:NNN` 而把文件名留给上下文（表头列名、行主语、章节标题）去推断的写法。原因：简写的文件归属依赖上下文，机器无法可靠校验，锚点失效时无人能发现。校验脚本 `docx/tools/check-docs.js` 只能覆盖显式锚点。 | 锚点静默失效、无法机检 |
| D-16 | **锚点宜带符号名**。写成 `lib/ui/app_theme.dart:65`（`_lighten`），使「行号 + 符号名」互为校验——行号漂移时仍可按符号定位。改动 `lib/` 中已被文档引用的文件时，应在同一次提交内更新对应锚点。 | 行号漂移后无法定位 |

## 6. 维护机制

### 6.1 触发式更新（强制）

> **本节是「改动 → 需同步文档」映射的唯一权威来源。**
> `08-工程纪律/文档与知识管理纪律.md` §1、`09-模板/PR描述模板.md` §3.6 只给出更粗的清单并指回本节；
> 三处内容若不一致，以本节为准（历史上该表曾在三处各写一遍，已发生漂移）。

| 触发事件 | 必须更新的文档 |
|---|---|
| 新增/删除 API 端点 | `04-数据与接口/API-端点清单.md`、`API-契约总览.md` |
| 新增/修改设置项 | `04-数据与接口/本地存储与配置项清单.md`、`03-模块详解/UI层-页面与组件清单.md` |
| 新增/修改数据模型字段 | `04-数据与接口/数据模型参考.md` |
| 改动缓存策略/上限 | `03-模块详解/服务层-缓存体系.md`、`04-.../本地存储与配置项清单.md` |
| 改动播放链路 | `03-模块详解/控制器层-PlayerController.md` |
| 新增平台原生能力 | `05-平台与原生/` 全部相关文档 |
| 版本发布 | `07-推进计划/里程碑与版本路线图.md`、`update.md` |
| 发现新缺陷/技术债 | `06-质量保障/已知问题与技术债台账.md` |

### 6.2 周期性回顾

- **每迭代结束**：更新 `07-推进计划/迭代排期与节奏.md` 的实际完成情况。
- **每季度**：全量校验一次 L1 契约文档（对照代码 + `api.json`）。

### 6.3 责任划分

单人维护期由项目负责人兼任全部文档责任；引入第二名贡献者后，按目录分配 owner，并在本节登记：

| `03-` | 模块作者 | 项目负责人 |

## 8. 约束与坑

| 编号 | 约束 | 说明 |
|---|---|---|
| R-01 | 本规范对**已存在**的文档不具备强制回改效力 | 规范升级后旧文档按「改动时顺带合规」处理，不做全量重写 |
| R-02 | `check-docs.js` 只做**结构**校验，不判断内容正确性 | 数字是否过时、结论是否成立，靠人工对照代码核查 |
| R-03 | 校验脚本对**代码块内文本**一律剥离 | 模板示例中的字段名不计入合规判定，头部声明必须真实存在于文件开头（D-13） |
| R-04 | 豁免清单（`EXEMPT_SECTIONS`）仅限索引与脚本生成物 | 见 `tools/README.md` T-03，不得为逃避检查而豁免 |
| R-05 | 单人维护期无交叉评审 | 文档正确性依赖作者自检，结构性错误只能靠脚本兜住 |
| R-06 | 行数、文件数等指标**手工同步**，天然易漂移 | 代码变更后若不回写，数字会静默过期（本轮核查即发现多处） |
