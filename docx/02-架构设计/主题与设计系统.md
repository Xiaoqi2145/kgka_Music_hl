# 主题与设计系统

## TL;DR

主题由 `AppTheme.light` / `AppTheme.dark` 两个工厂方法生成（`lib/ui/app_theme.dart:32-42`），底层是 `ColorScheme.fromSeed` + 一处集中 `copyWith` 覆盖；**不支持 Dynamic Color / Material You 取色**（`lib/` grep `dynamic_color`/`corePalette` 为 0 处），`themeMode` 固定为 `ThemeMode.system`（`lib/main.dart:143`），应用内没有深色模式开关。自定义全局背景图由 `_AppBackground` 实现（`lib/main.dart:186-315`），用「路径 + 缓存尺寸」做 `ImageProvider` 缓存键并走 `ResizeImage.resizeIfNeeded` 解码；提示统一走自建 `Toast`（`lib/ui/widgets/toast.dart`），**全项目 0 处 `SnackBar`/`ScaffoldMessenger`**。

### 2.4 Dynamic Color 支持情况

| 检查项 | 结果 |
|---|---|
| `dynamic_color` 依赖 / `DynamicColorBuilder` | 无（grep 0 处） |
| 系统壁纸取色（`corePalette`） | 无（grep 0 处） |
| Material You 体现 | 仅 `useMaterial3: true` + `ColorScheme.fromSeed` 的种子色派生 |
| 深色模式开关 | 无设置键；`themeMode` 硬编码 `ThemeMode.system`（`main.dart:143`） |

结论：**当前只支持「用户选种子色 + 跟随系统明暗」**。若要接 Material You，需要在 `main.dart:136-151` 增加动态配色来源并给 `ThemeController` 新增开关与持久化键（属新增契约，须同步 `../04-数据与接口/本地存储与配置项清单.md`）。

### 2.5 自定义全局背景图（`_AppBackground`）

挂载位置：`MaterialApp.builder` 内，包裹所有页面内容（`main.dart:152-157`），结构为三层 `Stack`：背景图 → 半透明遮罩 → 页面内容（`main.dart:288-311`）。

| 环节 | 实现 | 锚点 |
|---|---|---|
| 开关判定 | `!enabled \|\| path == null` 时直接返回 `child`，并释放监听 | `main.dart:272-275` |
| ImageProvider 缓存键 | `'$path@$cacheWidth*$cacheHeight'` | `main.dart:208-209` |
| 解码尺寸策略 | `ResizeImage.resizeIfNeeded(cacheWidth, cacheHeight, FileImage(File(path)))` | `main.dart:213-217` |
| 目标解码尺寸 | `mediaQuery.size * mediaQuery.devicePixelRatio`，向上取整 | `main.dart:280-286` |
| 渲染参数 | `fit: BoxFit.cover`、`gaplessPlayback: true`、`filterQuality: FilterQuality.low`、`errorBuilder` 返回空 | `main.dart:293-299` |
| 重绘隔离 | 图片层外包 `RepaintBoundary` | `main.dart:292` |
| 缓存保活 | 主动 `resolve` 并持有一个 `ImageStreamListener`，回调内 `imageInfo.dispose()`；键变化时先 `removeListener` | `main.dart:224-255` |
| 释放时机 | 关闭背景图（`:273`）、键变化（`:226`）、`dispose`（`:257-261`） |
| 遮罩色 | 深色 `0xFF06070A` / 浅色 `Colors.white`，alpha = `1.0 - opacity` | `main.dart:277-307` |
| 取图 | `ImagePicker.pickImage(source: gallery, imageQuality: 88, maxWidth: 2560, maxHeight: 2560)` | `theme_controller.dart:154-160` |
| 落盘位置 | `getApplicationDocumentsDirectory()/bg_custom<扩展名>`（扩展名取原文件名后缀，缺省 `.jpg`） | `theme_controller.dart:166-172` |
| 清除 | 删除文件 → `setBackgroundImagePath(null)` → `setBackgroundEnabled(false)` | `theme_controller.dart:182-194` |

设计意图（代码注释可核对）：「复制到应用文档目录，避免临时文件被系统清理」（`theme_controller.dart:166`）；「opacity 越大遮罩越透明，背景图越明显」（`main.dart:302`）。

| 无 Overlay 时 | 直接 `return`（静默忽略，不抛异常） | `toast.dart:35-36` |

**为什么不用 `SnackBar`**（可核对的四条理由）：

1. 全项目 `SnackBar` / `ScaffoldMessenger` 出现 **0 次**（grep 结果），提示实现是唯一路径。
2. `SnackBar` 需要一个可用的 `Scaffold` 与 `BuildContext`；而本项目大量提示发生在 `bottom sheet`、`dialog` 内部（如 `song_action_sheets.dart:284-299`、`app_update_widgets.dart:124-132`），这些位置的 `ScaffoldMessenger` 归属容易出错。
3. Toast 挂在根 `Navigator` 的 Overlay 上（`toast.dart:35`、`main.dart:142`），页面被 pop 后提示仍可见，且不随页面销毁而丢失。
4. 位置固定在底部 96 + 安全区（`toast.dart:155-157`），与迷你播放器、底部导航栏的常驻浮层互不遮挡。

| 动画 | `AnimationController(820ms)` + `repeat(reverse: true)`，仅在 `active && playing` 时运行（`:28-31`、`:47-55`） |
| 绘制 | 3 根圆角竖条，`barWidth = size.width / 5`、`gap = barWidth / 2`，高度系数 `.42+.36p`、`.72-.28p`、`.48+.44(1-|p-.5|*2)`，最终 `clamp(.28, .92)`（`:91-100`） |
| 暂停态 | `progress` 固定为 `.42`（`:70`） |

## 3. 约束与坑

| 编号 | 约束/风险 | 事实依据 | 影响 |
|---|---|---|---|
| R-01 | 没有设计令牌文件，圆角/间距/时长散落在 40+ 文件里 | grep `static const double (spacing\|gap\|radius\|padding)` = 0 处；114 处 `BorderRadius.circular` | 改视觉规范需要全局搜索替换，容易漏改 |
| R-02 | `appBarTheme.backgroundColor` 的两个分支都是 `Colors.transparent` | `app_theme.dart:107-109` | 该三元表达式是无效代码，易被误读为「背景图开启时才透明」 |
| R-03 | `AppTheme._lighten` 只提亮不检查对比度 | `app_theme.dart:154-156` | 用户选浅色种子（如樱花粉 `0xFFEC4899`）时深色模式主色可能对比度不足，属已知风险 |
| R-04 | 无 Dynamic Color，且深色/浅色完全跟随系统 | `main.dart:143` | 用户无法在应用内强制浅色/深色；需求提出时须新增设置键与 `ThemeMode` 状态 |
| R-05 | 背景图解码尺寸按「逻辑尺寸 × devicePixelRatio」计算，未设上限 | `main.dart:281` | 高 DPR 大屏设备会解码很大位图；虽有 `ResizeImage` 限制，但内存仍随屏幕增长 |
| R-06 | 背景图保活监听器的回调里 `imageInfo.dispose()` | `main.dart:228-231` | 这是刻意的「只保留缓存不占额外引用」写法；若未来改为在页面里直接用同一 provider，需复核是否会重复释放 |
| R-07 | 透明度上限只有 0.8，遮罩最低仍保留 20% 不透明 | `theme_controller.dart:73`、`main.dart:305` | 无法做到完全透明背景；这是为保证文字可读性的有意限制 |
| R-08 | `AdaptiveContentPadding` 的默认 680 会被调用方覆盖 | `adaptive_layout.dart:66` vs `app_shell.dart:133`（1150） | 同一套组件在不同页面宽度不同，视觉上会有差异 |
| R-09 | `isTablet`（最短边 ≥600）与外壳导航断点（宽 ≥720）是两套标准 | `adaptive_layout.dart:20`、`app_shell.dart:75` | 600–720 宽度的设备被判为平板（锁定横竖屏）却仍用底部导航，需注意测试覆盖 |
| R-10 | 只有歌词字号可调，其他文本不响应应用内缩放 | `player_page.dart:1853-1875` | 老年用户/大屏用户只能依赖系统字号；`TextTheme` 是固定值 |
| R-11 | Toast 同时只显示一条，新提示会打断旧提示 | `toast.dart:38-39` | 连续操作时前一条提示可能来不及被读到 |
| R-12 | 无 `SnackBar` 意味着也失去了 `ScaffoldMessenger` 的「页面级队列」语义 | grep 0 处 | 需要「必须被看到」的提示时不能简单加长时长，应考虑 dialog |
