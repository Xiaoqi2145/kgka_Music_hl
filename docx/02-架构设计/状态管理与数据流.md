# 状态管理与数据流

## TL;DR

项目**没有第三方状态管理库**：全局状态全部由 5 个 `ChangeNotifier`（`PlayerController` / `AuthController` / `DownloadController` / `ThemeController` / `LocalMusicController`）持有，在 `lib/main.dart:89-118` 手工装配，UI 用 `AnimatedBuilder` 订阅（`lib/` 共 39 处 `AnimatedBuilder`，其中 `lib/main.dart` 3 处、`lib/ui/` 36 处）。页面私有状态用 `StatefulWidget` + `setState`；高频播放进度走独立 `ValueNotifier`（`player.positionListenable`）旁路，避免整棵播放器树重建。

## 2. 设计说明

### 2.1 装配链（唯一注入点）

`lib/main.dart:28-54` → `lib/main.dart:89-118` 的顺序是硬约束：

1. `WidgetsFlutterBinding.ensureInitialized()` → `AppConfig.loadCustomBaseUrl()`（`main.dart:30-31`）：API 地址必须先于任何请求就绪。
2. `ApiClient` → `MusicApi`（`main.dart:33-34`）。
3. `AudioService.init` 创建 `MusicAudioHandler`（`main.dart:35-43`，通知渠道 `kgka_music_hl.playback`）。
4. `ThemeController()` + `await themeController.load()`（`main.dart:44-45`）：**首帧之前**完成，避免主题闪烁。
5. `runApp` → `_KaMusicAppState.initState` 内构造其余 4 个控制器并建立交叉引用，随后异步触发 4 个启动任务：`restorePlaybackSession()`（`:104`）、`auth.restore()`（`:106`）、`downloads.initialize()`（`:107-113`）、`ArtworkCacheService.instance.initialize()`（`:115`）。

### 2.2 登录态驱动的顶层切换

`lib/main.dart:189-206`：`AuthController.isRestoring` 初值为 `true`（`auth_controller.dart:27`），因此**首帧渲染的是 `AppShell`**，只有当 `restore()` 完成且未登录时才切到 `LoginPage`。`restore()` 在读到缓存数据后先 `isRestoring = false; notifyListeners()`，再 `await refreshProfile(silent: true)`——即「先出界面、后静默刷新」。

### 2.3 端到端数据流时序（一）：首页推荐加载

触发点：`HomePage.initState`（`lib/ui/pages/home_page.dart:60-75`）。

```mermaid
sequenceDiagram
```

两条路径的差别（可核对）：

| 路径 | 入口 | 首屏来源 | 网络请求 | 失败表现 |
|---|---|---|---|---|
| 进程内命中 | `home_page.dart:66-69` | `static _cachedData`（同 owner 时） | 后台 `_silentRefresh()` | 静默失败，`_silentRefresh` 空 catch（`:112-118`） |
| 磁盘缓存命中 | `home_page.dart:176-195` `_tryRestoreFromCache` | `cache.read(_cacheKeyForOwner(owner))`，TTL `AppConfig.homeCacheTtl` = 30 分钟（`app_config.dart:34`） | 后台 `_silentRefresh()` | 静默失败，保持缓存 |
| 缓存未命中 | `home_page.dart:196-198` | 骨架屏 `_HomeSkeleton`（`:280-282`） | 前台 `_load()`（`:120`） | `_ErrorView` + 重试按钮（`:286`） |

补充事实：

- 进程内静态字段 `static _HomeData? _cachedData`（`home_page.dart:43`）优先于磁盘缓存，因此同一进程内切回首页不会重新请求，只会静默刷新。
- **缓存 key 按 owner 隔离**：`_cacheKeyForOwner`（`home_page.dart:57-58`）在匿名态返回 `cache_home`，登录态返回 `cache_user_home_{userId}`。因此「登出不清理 `cache_home`」只影响匿名口径那次写入；已登录用户的首页缓存走 `cache_user_home_*`，由 `CacheService.clearUserCache` 按 `cache_user_` 前缀清理（`cache_service.dart:251-257`）。
- 缓存写入发生在 SWR 的 `onData` 回调（`home_page.dart:161-166`），key 由 `_cacheKeyForOwner(owner)` 决定。

### 2.4 端到端数据流时序（二）：点播一首歌

触发点示例：`lib/ui/pages/home_page.dart`（首页歌曲行）、`lib/ui/pages/search_page.dart`（搜索结果行）、`lib/ui/pages/home_page.dart`（电台播放）。全部收敛到 `PlayerController.playSong`（`player_controller.dart:669-670`，转调私有 `_playSong` `:704`）。


关键分支与锚点：

| 分支 | 判定 | 锚点 | 结果 |
|---|---|---|---|
| 同曲续播 | 点击的是当前曲且音源已加载 | `player_controller.dart:704-767` | 不重新解析，必要时只换队列 |
| 本地命中 | `downloadController?.localSourceFor(song, quality)` 非空 | `player_controller.dart:1012`、`:2928`、`download_controller.dart:298`、`:310` | 优先已下载（同音质），其次播放缓存 |
| 云盘歌曲 | `song.isCloudDrive` | `:1043`、`:1265`、`:1698` | `api.cloudSongUrl(song)` |
| 智能音质降级 | `smartQualityEnabled` | `:770-776`、`_nextLowerQuality` `:1306` | 按 `_nextLowerQuality` 链依次重试 |
| 预加载歌曲预解析 | 剩余 ≤30 秒且满足触发条件 | `player_controller.dart:1618+`（`_prepareNextSourceIfNeeded`）、调用点 `:183` | 只缓存下一曲地址与响度，**不追加原生子源**；消除切歌时的网络往返，但音频接续仍是显式单音源替换 |
| 边播边缓存 | 网络音源，稳定播放 30 秒 | `:1429` | `DownloadController.cacheForPlayback` |

高频更新的旁路设计：`audioPlayer.positionStream` 回调只更新 `positionListenable`（`player_controller.dart:175-186`、`_setPositionBase` `:2792` 附近），不调用 `notifyListeners()`；注释明确写为「位置高频更新通过 positionListenable 发送，避免触发全局 ChangeNotifier」（`:185`）。

### 2.5 `setState` 与 `ChangeNotifier` 的边界

`lib/` 共 133 处 `setState` 调用。按职责划分：

| 归属 | 典型内容 | 锚点示例 |
|---|---|---|
| 页面私有、生命周期与页面绑定 | `Future` 句柄、加载/错误标志、排序与筛选、搜索词、分页游标 | `home_page.dart:194`、`playlist_detail_page.dart:223`、`:312`、`search_page.dart:71` |
| 页面内 UI 偏好（仅本页可见） | 歌词字号 `_lyricScale`、歌词显示模式 `_displayMode`、Tab 下标 | `player_page.dart:1874`、`:1895`、`app_shell.dart:105` |
| 高频镜像（避免订阅控制器） | `_position`、`_frameActiveIndex`、`_scrollStretch` | `player_page.dart:1210`、`:2453`、`:2766` |
| 应交给控制器（现状已交给控制器） | 播放、登录、下载、主题、本地扫描 | 见 §1.1 |

已核验：`lib/ui/` 中**不存在**对控制器字段的直接赋值（grep `player\.<name> = ` / `auth\.<name> = ` / `downloads\.<name> = ` / `theme\.<name> = ` / `localMusic\.<name> = ` 均为 0 处），所有写入都经过控制器方法。

## 3. 约束与坑

| 编号 | 约束/风险 | 事实依据 | 影响 |
|---|---|---|---|
| R-01 | 控制器字段全部是 **public 可变**，没有 setter 保护 | `player_controller.dart:331-391`、`auth_controller.dart:27-35` | 任何代码都可以绕过方法直接改状态而不触发持久化；当前靠纪律维持 |
| R-02 | `position` 存在三份真相：`player.position`（控制器低频）、`positionListenable`（高频）、页面 `_position`（`setState` 镜像） | `player_controller.dart:335`、`:439`、`player_page.dart:1184`、`:1210` | 三者的同步依赖 `_isSeeking` / `_isScrubbing` 标志，改动 seek 逻辑时必须同时检查这三处 |
| R-03 | `home_page.dart:43` 的 `static _cachedData` 跨实例共享（另有 `_cachedDataOwner` 做账号隔离） | `home_page.dart:43-44`、`:66` | 同一进程内切回首页命中进程缓存，不重新请求；换账号时靠 owner 比对失效 |
| R-04 | 匿名首页缓存 `cache_home` 不随登出清理（登出只清 `cache_user_` 前缀） | `cache_service.dart:88-89`、`:251-257` | 匿名数据本身匿名可访问，无泄露；但若将来 `cache_home` 承载账号相关字段，必须重新评估 |
| R-05 | `AnimatedBuilder` 粒度偏粗 | `player_page.dart:130` 监听整个 `player` | 任意 `notifyListeners()` 都会重建播放页；当前靠 `TickerMode`（`:128`） + `positionListenable` 缓解 |
| R-06 | `PlayerController.notifyListeners()` 调用点极密（下载进度、歌词、定时器都会触发） | `download_controller.dart:367-418`、`player_controller.dart:479` | 睡眠定时器每秒一次 `notifyListeners()`，订阅 `player` 的页面会每秒重建 |
| R-07 | `ThemeController` 未在 `main.dart.dispose` 中释放 | `main.dart:139-148` | 进程级单例，实际上无害，但登记为技术债以免误判为遗漏 |
| R-08 | `AuthController.restore()` 会在缓存就绪后提前 `notifyListeners()`，随后 `refreshProfile` 再次通知 | `auth_controller.dart:244-246` | 顶层 `AnimatedBuilder` 会重建两次；这是刻意的「先出界面」取舍 |
| R-09 | 页面 `setState` 前必须判 `mounted`，但并非所有调用点都判 | `playlist_detail_page.dart:223`（未判）对比 `:393`、`:401`（已判） | 快速退出页面时存在 `setState after dispose` 的理论风险，待核实是否有实际崩溃 |
| R-10 | `LocalMusicController` 构造即触发异步扫描（`_loadSettings`），扫描期间无法取消 | `local_music_controller.dart:7-8`、`:21+` | 大目录会持续占用 IO，且 `dispose` 不中止扫描 |
