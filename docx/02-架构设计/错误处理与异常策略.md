# 错误处理与异常策略

## TL;DR

当前错误处理是**「分层各管一段」**：传输层抛 `ApiException`，控制器把错误写进 `errorMessage` 字段由 UI 展示，服务层大量 **静默吞异常**（`catch (_) {}` 共 22 处）并降级。全项目 105 处 `catch`、仅 6 处 `rethrow`、40 处 `debugPrint`。**没有统一异常类型、没有错误码、没有上报**——这是可观测性得 1.0 分的直接原因（见 `07-推进计划/工程化推进总纲.md` §1）。

---

## 1. 异常类型现状

| 类型 | 定义 | 抛出方 | 携带信息 |
|---|---|---|---|
| `ApiException` | `lib/core/api_client.dart:11-19` | `ApiClient` | `message`、`statusCode` |
| `TimeoutException` | `dart:async` | `ApiClient`（deadline 超时） | message |
| `http.ClientException` | `package:http` | `ApiClient`（网络失败） | message |
| `FormatException` | `dart:core` | JSON 解析 | message、offset |
| `Exception('这首歌暂时没有可播放地址')` | 内联 | `PlayerController` | 无结构化信息 |
| `PlayerException` | `just_audio` | 音频引擎 | `code`、`message` |

> ⚠️ **没有业务错误码体系**。`ApiException.statusCode` 是 HTTP 状态码，业务失败（如 `_isSuccess == false`）只体现在 message 字符串里。

---

## 2. 分层错误处理职责

| 层 | 职责 | 实际做法 |
|---|---|---|
| 核心层 `ApiClient` | 区分可重试/不可重试错误，转换超时与网络异常 | 5xx/超时/ClientException 重试；4xx 与 FormatException 直接抛 |
| 服务层 `MusicApi` | 把响应体转成领域模型，业务失败抛 `ApiException` | 用 `_isSuccess` 判断，失败拼接 hint 与错误码 |
| 服务层（缓存/下载/歌词） | **降级优先，不打断主流程** | `catch (_) {}` + 返回 null/空；日志可选 |
| 控制器层 | 保存错误状态供 UI 展示；必要时自动恢复 | `errorMessage = error.toString()` + `notifyListeners()` |
| UI 层 | 展示错误与重试入口 | 读 `errorMessage` / `isLoading`，渲染错误视图 |

## 4. 静默吞异常分布（`catch (_) {}` 共 22 处）

| 文件 | 处数 | 典型场景 |
|---|---|---|
| `lib/controllers/player_controller.dart` | 8 | 设置恢复、会话持久化、歌词、桌面歌词、音效 |
| `lib/ui/pages/settings_page.dart` | 4 | 缓存大小查询、目录清理 |
| `lib/controllers/download_controller.dart` | 2 | 索引加载、缓存清理 |
| `lib/ui/pages/playlist_detail_page.dart` | 2 | 缓存读写 |
| 其余 8 个文件 | 各 1 | 认证、主题、缓存、搜索历史、搜索页、歌单页 |

**判定**：

- ✅ **可接受**：降级到占位图/空列表、清理操作的失败、非关键持久化。
- ❌ **不可接受**：登录态恢复、播放失败、下载失败、索引持久化——这些必须至少记一条结构化日志。

## 7. 约束与坑

1. **`errorMessage` 是字符串**：UI 无法区分错误类型，只能原样展示（可能出现英文异常栈）。
2. **`errorMessage` 只在下次 `playSong` 时清空**：用户不操作则一直显示。
3. **`_playerErrorSub` 自动重播**：持续错误会反复触发加载，虽有 `_isHandlingPlayerError` 但仅防单次重入。
4. **`ApiException.message` 直接放响应体**：可能包含后端返回的原始 HTML/JSON，展示不友好且可能泄露内部信息。
5. **无 `runZonedGuarded`**：未捕获的异步异常会直接终止 isolate（移动端表现为崩溃）。
6. **重试与幂等**：`post` 默认 `allowRetry = false`（`api_client.dart:47`），但调用方需自行确认；`sendLoginCode` 等写操作不可重试。
7. **业务失败判定只覆盖登录链路**：`_isSuccess`（`status == 1`）仅在 `music_api.dart:44` 与 `:77` 被调用，其余端点对 `status != 1` 一律静默当成功——UI 只会看到「空数据」，看不到错误原因（见 TD-40）。
8. **`ApiClient` 末尾 `throw ApiException('请求失败，已重试 N 次')` 为死代码**：循环内所有分支都已 return 或 rethrow。
9. **`FormatException` 重试分支不可达**：`jsonDecode` 异常已在 `_processResponse` 内被捕获并降级为返回原始字符串（`api_client.dart:139-143`）。
