# 路由与导航

## TL;DR

全项目使用 **Navigator 1.0 + 匿名路由**：无路由表、无 `pushNamed`、无 `onGenerateRoute`（`lib/` grep 结果为 0 处）。顶层只有一个 `Navigator`，`home` 在 `LoginPage` 与 `AppShell` 之间切换（`lib/main.dart:158-175`）；`AppShell` 内部用 `IndexedStack` 承载「首页 / 我的」两页（`lib/ui/pages/app_shell.dart:80`），页面级跳转一律 `Navigator.of(context).push(MaterialPageRoute(...))`（26 处），弹层一律 `showModalBottomSheet`（18 处）或 `showDialog`（11 处）。

## 2. 设计说明

### 2.1 应用外壳：底部导航与侧边栏

`_AppShellState` 只持有一个局部状态 `_index`（`app_shell.dart:46`），两种导航形态由宽度决定：

| 判定 | 条件 | 组件 | 锚点 |
|---|---|---|---|
| 侧边栏 | `size.width >= 720` | `NavigationRail`（`labelType: all`） | `app_shell.dart:75`、`:92-128` |
| 底部导航 | `size.width < 720` | `BottomNavigationBar` + `BackdropFilter(sigma 18)` | `app_shell.dart:134-184` |

两页定义（顺序即 `_index` 顺序）：

| 下标 | 页面 | 构造参数 | 锚点 |
|---|---|---|---|
| 0 | `HomePage` | `api`、`auth`、`player`、`cache` | `app_shell.dart:53-58` |
| 1 | `LibraryPage` | `api`、`auth`、`player`、`downloads`、`theme`、`localMusic` | `app_shell.dart:59-66` |

导航行为细节：

- `_pages` 在 `initState` 构造一次（`app_shell.dart:52-67`），由 `IndexedStack` 保持两页状态常驻（`:80`），切换 Tab 不销毁页面、不重置滚动位置。
- 侧边栏与底部导航共享同一个 `_index`，回调都是 `setState(() => _index = value)`（`:97`、`:158`）。
- 迷你播放器是 `Stack` 里的常驻浮层，位置随导航形态变化：`bottom = bottomInset + (useNavRail ? 16 : kBottomNavigationBarHeight + 10)`（`:82-88`）。
- 外壳内容被 `AdaptiveContentPadding(maxWidth: 1150)` 包裹（`:133`）——注意这里**覆盖**了 `AdaptiveLayout.contentMaxWidth` 的默认 680。
- 外壳在 Android 上包一层 `PopScope(canPop: false)`（`:191-198`），返回键不退出路由而是调用 MethodChannel `kgka_music_hl/screen` 的 `moveTaskToBack`（`:44`、`:201-208`）；非 Android 平台直接返回 `Scaffold`（`:187-189`）。

### 2.8 横竖屏切换对路由的影响

| 机制 | 规则 | 锚点 |
|---|---|---|
| 方向锁定 | `isTablet \|\| landscapeEnabled` → 4 向解锁；否则仅 `portraitUp` | `theme_controller.dart:107-127` |
| 锁定时机 | 每次 `KaMusicApp.build` 调用 `applyOrientations(AdaptiveLayout.isTablet(context))`；同值不重复调用 | `main.dart:135`、`theme_controller.dart:108-113` |
| 播放页例外 | `initState` 强制解锁 `portraitUp + landscapeLeft/Right`（手机也能横屏播放），`dispose` 恢复 | `player_page.dart:52-56`、`:66-78` |
| 歌单详情 | 竖屏 push 整页；横屏改为右侧悬浮面板（**同一个页面类**，两种承载方式） | `playlist_detail_page.dart:33-92` |
| 播放队列 | 竖屏 bottom sheet；横屏右侧抽屉（`showGeneralDialog` 或 `OverlayEntry`） | `mini_player.dart:191-195`、`player_page.dart:203-213` |
| 歌单网格 | `width >= 720` 时切换为 `GridView`（`maxCrossAxisExtent: 340`、`mainAxisExtent: 72`） | `library_page.dart:1024-1035` |
| 平板断点 | `shortestSide >= 600` 判为平板 | `adaptive_layout.dart:20-23` |
| 内容宽度约束 | `width < 600` 不加约束；否则居中并限制宽度 | `adaptive_layout.dart:58-71` |

要点：**路由栈不因旋转而重建**。旋转只改变承载形态（push ↔ dialog）与布局参数；`IndexedStack` 中的页面状态、`Navigator` 栈内容都不受影响。唯一的例外是 `openPlaylistDetail` 在旋转后若再次点击会以新的形态打开（原路由或原 dialog 仍在栈上）。

## 3. 约束与坑

| 编号 | 约束/风险 | 事实依据 | 影响 |
|---|---|---|---|
| R-01 | 无命名路由与路由表，所有跳转都是匿名 `MaterialPageRoute` | grep `pushNamed\|routes:\|onGenerateRoute` = 0 处 | 无法做深链接、无法按路由名做埋点或权限拦截；新增页面必须手工在所有入口补 `push` |
| R-02 | `showAudioEffectsSheet` 名为「sheet」，实际是 `Navigator.push` 到整页 | `audio_effects_sheet.dart:6-13` | 阅读代码时容易误判为弹层，改样式时选错载体 |
| R-03 | `downloaded_songs_page.dart:241` 的 bottom sheet 缺少 `showDragHandle` 与 `backgroundColor` | 对比其余 17 处 | 视觉与交互不一致（无拖拽手柄、背景色跟随默认） |
| R-04 | `_AppShellState` 只用 `_index` 表达导航位置，未与路由同步 | `app_shell.dart:46`、`:97`、`:158` | 在子页面按返回键回到外壳时，Tab 仍是离开时的下标（符合预期），但无法通过 URL/深链接直达某个 Tab |
| R-05 | 横屏下同一页面有两种承载（push 整页 / 右侧面板），两处都新建了 `PlaylistDetailPage` 实例 | `playlist_detail_page.dart:35-44`、`:69-75` | 状态不共享；从横屏面板关闭再竖屏打开会重新走缓存 + 网络流程 |
| R-06 | 播放页横屏队列用 `OverlayEntry` 而非路由 | `player_page.dart:216-269` | 返回键不会关闭该抽屉，只能点遮罩或关闭按钮；`OverlayEntry` 需手动 `remove`，泄漏风险靠 `entry.remove` 保证 |
| R-07 | Toast 挂在根 `navigatorKey` 的 Overlay 上 | `toast.dart:35-54` | 页面被 pop 后 Toast 仍可显示（优点）；但同时只允许一条（新 Toast 会移除旧的，`:38-39`） |
| R-08 | API 地址编辑对话框在登录页与设置页各实现一份 | `login_page.dart:145`、`settings_page.dart:397` | 两份逻辑需同步维护 |
