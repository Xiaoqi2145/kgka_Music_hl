# 任务分解 WBS（细粒度）

## TL;DR

共 **62 个任务**，分属 8 个里程碑。每个任务都给出：前置依赖、产出物、**可验证的验收标准**、估算（人日）。估算总量 **125.5 人日**（单人维护约 25 周，与总纲的 20 个迭代基本吻合；按每迭代 6.3 人日摊派，实际可承诺 5 人日/迭代，缺口见 `迭代排期与节奏.md` §5.2）。**任务编号是全局唯一标识，纪律文档与台账均引用它。**

---

## 0. 使用说明

| 字段 | 含义 |
|---|---|
| 编号 | `T-M<里程碑号>-<两位序号>`，全局唯一，不复用 |
| 估算 | 人日（1 人日 = 6 小时有效工作） |
| 前置 | 必须完成的任务编号；「—」表示无前置 |
| 验收 | **可执行的检查动作**，不是「感觉可以」 |
| 台账 | 关联的 `TD-xx` / `C-xx` / `K-xx` / `A-xx` |

**完成定义（DoD，适用于所有任务）**：

1. 代码通过 `flutter analyze` 零警告；
2. `dart format` 无差异；
3. 受影响测试通过，新增逻辑有测试；
4. 触及契约的文档已同步更新；
5. 台账相关条目状态已更新。

## 约束与坑

| 编号 | 约束 | 说明 |
|---|---|---|
| W-01 | 估算为**单人**口径，不含沟通与返工 | 多人协作需另行折算 |
| W-02 | 任务之间有硬依赖（见各表「前置」列），不可并行跳过 | 尤其 M1 → M2 → M3 |
| W-03 | 编号一旦分配不再复用；任务拆分时新增子编号（如 `T-M2-01a`） | 便于台账与提交信息引用 |
| W-04 | 「验收标准」必须是可执行动作，不接受「功能正常」这类描述 | 评审时逐条核对 |
| W-05 | 若某任务连续两个迭代未推进，必须重新评估是否仍需要 | 防止计划僵化 |
| W-06 | 完成定义（DoD）适用于**所有**任务，不因任务小而豁免 | 见 §0 |
